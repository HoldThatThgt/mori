## 改了什么、为什么

负责人的一轮（会话 `01a175e1`）有 17 条带工具调用的回复、28 次调用、18 个思考块，最后的回答上面一直摊着 18 个
"Thought process"和 28 张工具卡；"finished/paused"在 Mori 里对应正常结束、按停止、等你批准或回答、协作模式交给后台之后对话空闲。
照 Claude 桌面版（Code 一栏的步骤组：运行中 "Working"，结束后 "{n} steps"）：

- 界面的纯函数（`app/src/renderer/src/state/turns.ts`）：`stepGroups` 按已显示的对话流算步骤组——同一轮里连续的思考块
  （有字的）与工具卡，跨几条助手回复；有字的正文或任何不是助手回复的一项结束一组，你的消息与程序投递还结束一轮；
  组里至少有一张工具卡。组在"后面有正文且调用都已结束"或"这一轮已经结束"时折起。`stepsLabel` 是 Claude 的
  `{count, plural, one {# step} other {# steps}}`（`vAKAnIbJ4M`），有 Failed 的调用时空一格接 Claude 的
  `· {failedCount, plural, one {# failed} other {# failed}}`（`HVw2b9gU1w`）。`itemSteps` 按组和你的展开、收起算出
  每条回复怎么画（哪些块收着、摘要行画在哪一块前面）；`foldedIn` 给跳转用。
- `AssistantMessage.tsx`：思考块和工具卡外面总是包一层 `<div>`，在组里时带 `data-step-group`，收着时这一层 `hidden`
  （仍在页面里；不在组里时也是同一个 `div`，思考块进组时不会重新挂载、丢掉你点过的展开）；
  组在已显示部分的第一块前面画摘要行 `<button class="step-group" data-testid="step-group" data-group aria-expanded data-no-quote>`；
  整条都收着的回复 `.assistant-message` 本身 `hidden`（不留 24px 的空白，`data-item-key` 照旧，跳转找得到）；
  合并会话里工具卡下面的回执不包进去，卡收着时照常显示，看起来就在摘要行下面，页面里仍紧跟在它的卡后面。
- `Transcript.tsx`：`useSteps` 算组（`useReplyActions` 多给出"最后一轮在运行"，与回复操作行同一个判断），你的展开、收起按组记在
  这个会话面板里，`sessionId` 变了（后台进程重启后重新打开）就回到折起；`ItemView` 的 memo 按内容比步骤组视图
  （流式输出时别的回复不跟着重画）；`useQuoteJump` 在滚动、高亮之前先展开要露出来的组（`flashKeys` 算要高亮的项，
  `jumpFolds` 算要展开的组），展开后重画、再跑一次。
- `chat.css`：摘要行同思考块的标题行（12px、`--color-faint`、悬停变 `--color-muted`），`▸` / `▾` 用 `::before` 写，
  `content` 的替代文字为空，读屏名就是那行字。
- 文档：chat.md"步骤组"（状态表）、tool-cards.md、selection.md、session-refs.md、memory-page.md、memory-chat.md、
  team-stream.md、TaskBoard 规格 §13.2 与 TB-08、记忆规格 §10.2 第一行、app-v0.md §5.4/§5.5 的两处注、ui-strings.md、

## 按推荐替负责人定下的（负责人没单独回答）

1. 摘要行的文字用 Claude 的 "{n} steps"（"1 step"、"46 steps"），步数 = 思考块数 + 工具调用数，同 Claude 的算法
   （诊断决定 1 的推荐）；不做 "Read 26 files, ran 2 commands" 那种按工具分的摘要（Mori 的 TaskBoard、memory、MCP 工具都要另想词）。
2. 只数 "Failed" 的调用，加 " · k failed"（工作包写的；文字是 Claude 的 `HVw2b9gU1w`）；"Denied"、"Stopped"、"Interrupted" 不另标：拒绝是你自己点的，
   停止、中断时对话流里已有 "Stopped · …" 一行或错误卡（defaults.md）。
3. 正文跟在后面就折（同 Claude），不等整轮结束（诊断决定 2 的推荐）。
4. 进行中的组每一步都显示，同以前（诊断决定 3 的推荐），不像 Claude 只显示最后 3 个；进行中也没有 "Working" 那一行
   （阶段行已经说了在做什么）。
5. 组里还有没结束的调用（"Preparing…"、"Queued"、"Waiting for your approval"、"Running…"）时，后面有正文也不折：有的模型在
   同一条回复里先调用、后写字，调用要等这条回复结束才执行；同 Claude 等你批准、回答时组保持展开（诊断里的 `turnWaitsOnUser`）。
6. 只有思考块、没有工具卡的一段不成组，照旧是一个 "Thought process"（诊断的推荐；折成 "1 step" 不省一行，defaults.md）。
7. 任何不是助手回复的一项都结束一组，包括以后新加的提示行：WP-10 要加的 "Task mode on/off" 一行不用另写规则就不进组。
8. 收着的块留在页面里（`hidden`），读状态、标题的测试照常读得到；整条收着的回复本身也 `hidden`。
9. 你的展开、收起只在这个会话面板开着时有效（同思考块），关掉会话、重启、后台进程 Restart 之后重新打开、界面重新载入后
   回到折起（defaults.md）。组的标识取组里最后一块（`<回复 key>:<块下标>`），折起之后不再变，"Scroll up to load earlier messages"
   载入更早的消息把组接长时也不变；被它切开的组的摘要行在已显示的第一块前面，步数只算已载入的。
10. 跳转（工作包写的"Jumps (Jump to source, quote jumps, session-ref highlights) expand a folded group first"）：引用的是
    选中的文字、文字在收着的块里时展开那一组；其余按消息高亮的，先展开要高亮的消息里收着的组——落在一条消息上（记忆页的
    Jump to source，找不到选中的文字时）是这条消息里的组（依据是 memory 调用的回复时，展开后 memory 卡看得见），整条回复的引用
    是这一轮里的组，会话引用是引用的几轮里的组。展开的组同你点开的一样，留在展开状态。（开发阶段原来定的是高亮整轮时不展开，
    评审指出与工作包不符，已改成工作包写的，见"评审意见与处理"第 1 条。）
11. 回执不挪位置：卡收着时回执照常显示，页面里仍紧跟在它的卡后面，所以 TB-08、TB-10 现有的"回执在那张卡下面"的检查不用改。
12. （集成时加）折起后已显示的部分滚不动时，在对话流顶部向上滚轮也载入更早的 50 条（同滚到顶部，不自动多载入，键盘没有另加；
    defaults.md）。原来只认 `scroll` 事件，50 条以前总比一栏高；折起后可能不满一栏，"Scroll up to load earlier messages"
    一直在却载入不了。
13. （集成时定）WP-10 的模式提示（`Task mode on` / `Task mode on until done` / `Task mode off`）照第 7 条结束一组、不结束一轮，
    chat.md"步骤组"把它写进结束一组的各项和"一直显示"里。

### 集成时发现并改的

1. **WP-10 的模式提示（开发阶段写给集成的那一条）**：`Task mode on/off` 是对话流里单独的 `team-mode` 项，不是助手回复，结束一组、不结束一轮，
   画在 `AssistantMessage` 之外，从不在 `[data-step-group]` 里。补了单元测试、`tb-replay` 的 TB-58 检查（`tb-team` 四行、
   `tb-receipts` 两行）和 chat.md"步骤组"的写法（上面"测试"的"集成时加的"）。
2. **折起后载入不了更早的消息（本包引起的缺陷）**：给"只载入了一部分"一行补界面用例（`m1-replay` `steps-history`）时第一次跑失败：
   只载入最近 50 条、组折成一行"49 steps"之后已显示的部分不满一栏（`scrollableBefore: false`），向上滚轮没有 `scroll` 事件，
   "Scroll up to load earlier messages"一直在却载入不了（以前 50 条总比一栏高，不会这样）。改：对话流在顶部向上滚轮也载入
   （`Transcript.tsx` `.conversation` 的 `onWheel` 调 `useLoadEarlier` 的同一个函数，它自己判断在不在顶部、还有没有更早的）；
   chat.md"更早的消息""只载入了一部分"两行、`defaults.md` 新一行（上面第 12 条）。改后 `steps-history` 3/3，原来的
   `m1-replay` `history` 与 `m4-app` `longHistory` 照常通过。
3. **回答 8 缺的用例**：开发阶段的记录没有"状态表各行的用例"表；对着这包改过的每一行查，缺两处：chat.md"只载入了一部分"（只有单元
   测试，补 `steps-history`，见第 2 条）和 selection.md"回复里的选区"的"找不到文字时先展开这条回复里折起的组"（补 `m4-app`
   `unfoundQuoteFold`）。表在下面"状态表各行的用例"。
4. **两个没有 `--only` 的套件**：`m0-shell`、`m6-app-mcp-shared` 照别的套件加上 `--only`（测试分层第 2 条），这样只跑这包改过的读卡
   路径，不跑整套。
5. **快速集的时间**：第一次快速集自己报 99 秒（连构建 117 秒），比 WP-10 集成时的 79–82 秒慢，主要是 `mem-replay`（约 36 秒）。

## 给负责人看的

- 步骤组折起后，一个长会话的最近 50 条可能不满一栏、滚不动；这包加了"在顶部向上滚轮也载入更早的"（defaults.md）。键盘（PageUp、
  Home）在滚不动时仍载入不了；要不要改成自动多载入或让键盘也能载入，请你走查时定。
- 会话引用跳过去时，把引用的几轮里折起的组都展开（照工作包），几轮步骤多时看到的是摊开的步骤。
- 失败只标 Failed 的调用（" · k failed"）；拒绝、停止、中断不另标（defaults.md）。
