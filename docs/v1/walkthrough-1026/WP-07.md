依据：2026-10-26 负责人走查（[walkthrough-1026-checks.md](../walkthrough-1026-checks.md)）的 M4、M15；诊断、复核与跨组计划在会话 scratchpad 的
`diag1.json`（M4、M15）与 `plan1.json`（WP-07、冲突第 9 条）。状态表 [customize-agents-md.md](../screens/customize-agents-md.md)。

## 改了什么、为什么

| # | 负责人原话 | 改动 |
| --- | --- | --- |
| M4 | the AGENTS.md should put in customize rather setting | 用户级 AGENTS.md 的编辑器连同项目加载的文件、token 数，从设置页整节挪到 Customize，作为第一节 `AGENTS.md`；设置页只剩 `Models`、`UI issues` |
| M15 | budget for AGENT.md is too short, expand to 2000tokens | 提醒线由 500 改为 2,000：`shared/memory.ts` 新加 `AGENTS_LIMIT = 2000`，记忆四种的 `MEMORY_LIMIT` 仍是 500；警告文字 `Over 2,000 tokens. …`，合计 `<total> / 2,000 tokens`，数字按千分位写 |

给负责人的说明（M15，诊断时核对过代码，没有打印文件内容）：Mori 从来不截断 AGENTS.md，模型每次拿到的都是全文；“500”只是设置页和记忆页显示警告的那条线。
Mori 的 token 数是估算（中文每个字算 1，其他文字约 4 个字符算 1），按这个算法你的用户级 AGENTS.md 约 663，所以看到了警告。改成 2,000 只是把提醒线挪高，
模型收到的内容不变。

具体做法：

- Customize（`ToolsPage.tsx`）：分节加 `agents`，有会话时 `AGENTS.md`、`Built-in tools`、`Skills`、`MCP`、`Plugins`，没有会话时 `AGENTS.md`、`Skills`、`Plugins`；
  进入时落在 `AGENTS.md`。这一节不经过 `tools.get` 的读取中与读取失败（`InfoContent` 只包另外四节），自己读 `agents.get`。
- 跟随：`Followed` 加 `cwd`；`AgentsSection` 收 Customize 跟随的会话（`project`），不再在进入时取一次焦点会话。会话还在打开中时先不带会话读（编辑框可用），
  项目一栏 `Loading…`，打开好后带会话再读；跟随的会话换了（归档、删除、重启后台进程后重新打开）时重新读，只认最后一次读取，编辑框里没保存的字不丢。
- 离开：Customize 换分节（点、↑ ↓）经过 `guardLeave`；点当前分节不问；已经在 Customize 时点侧栏 `Customize` 什么都不做（`openTools` 同 `openMemory` 先返回）。
  其余离开入口（Back to app、侧栏会话、New session、Open folder…、Ctrl+N、Memory、Settings、F8 的 View in Settings）原来就经过离开检查，不用改。
- 记忆页 `AGENT`：`Edit in Settings` 改为 `Edit in Customize`（`openTools('Open Customize → AGENTS.md')`，有未保存的条目编辑时先问）；合计与警告按 `AGENTS_LIMIT`、千分位。
- 设置页：去掉 `agents` 分节；`SettingsSection` 只剩 `models | issues`；`selectSection` 不再经过 `guardLeave`（设置页里没有会登记离开检查的编辑器）；
  `focusedSession` / `FocusedSession` 删掉（只有 AGENTS.md 一节用）。
- 样式：AGENTS.md 的规则从 `settings.css`、`memory.css` 挪到 `tools.css`；根元素从 `.settings-section[data-section="agents"]` 改为 `.agents-section`
  （`data-testid="agents-section"`），“This project doesn’t load …”一行用 Customize 的 `tools-empty`。
- 文档：状态表 `docs/v1/screens/customize-agents-md.md`（新，取代 v0 settings.md 的 AGENTS.md 一节与 settings-issues.md 的 token 一节，那两处只留指向）；
  `docs/v0/screens/tools.md` 外框、`settings.md`、`layout.md`、`README.md`，`docs/v1/screens/settings-issues.md`、`memory-page.md`、`models-settings.md`、`README.md`；
  规格 `docs/specs/memory.md` §0、§3、§10、§10.1、§10.3（2026-10-26 注）、§10.8、§10.11、§14 MEM-16、§14.4；proposal §5.2 加注（不改表里的数字：
  AGENT 一行 2000，整份 prompt 约 4000，加事实约 4500）、§7、§11、§16；方案 `docs/app-v0.md` 5.12、5.13、M6 走查 2；`docs/v0/ui-strings.md`；
  `docs/v1/memory-checks.md` 记为负责人的决定（不是临时默认值，不登记在 `defaults.md`）。

## 按推荐替负责人定下的

诊断给了选项、负责人没单独回答，照推荐（`plan1.json` WP-07 的 rationale）：

1. 分节名叫 `AGENTS.md`（同术语表的文件名），不用 Claude 桌面版 Memory 面板的 “Instructions”。之后 M20 会加 `Customize › Agents`，两个名字容易混，
   到写 M20 规格时再定（`plan1.json` 冲突第 9 条）；这一包保持 `AGENTS.md`。
2. 放在第一节，Customize 打开就落在它（它是唯一一节在有没有会话时都在的）。
3. 2,000 比的是全部加载文件的合计（同原来），不是每个文件。

## 实现时定下的（临时，走查时可以改）

4. 没有会话时 Customize 顶部写 `No open session. Only AGENTS.md and user-level skills and plugins are listed.`（诊断的建议文字）。
5. 跟随的会话还在打开中、或换了会话还没读到时，项目一栏写 `Files loaded by <项目名>` 和 `Loading…`；这时不显示 `agents-over`（不拿上一个会话的合计提醒）。
6. 重新读取失败（已经读到过）时把 `Couldn’t load AGENTS.md: <原文>` 显示在这一节顶部，读到过的内容和编辑框留着；原来只记日志。
7. 每个文件的 token 数也按千分位写（`2,099 tokens`），与合计一致；诊断只提到合计。
8. 从记忆页进来记 `Open Customize → AGENTS.md`（同 `Open Settings → Models` 的写法）；侧栏仍记 `Open Customize`。
9. 没有照诊断第 4 条把 Customize 的当前分节搬进 `state/tools.ts` 加落点：AGENTS.md 是第一节，进入 Customize 本来就落在它，`Edit in Customize` 只要打开 Customize，
   不需要落点；分节仍是 `ToolsPage` 里的 `useState`（最简单的做法）。
10. Customize 的不信任说明在 AGENTS.md 一节照样显示（说的是技能与设置，AGENTS.md 不受信任控制、照常列出）。
