# WP-04 删掉长输入、取消两个探针 检查记录

依据：2026-10-26 负责人走查（[本轮记录](../walkthrough-1026-checks.md)）第 M7 条，原话
“Verify / Long-input test… / Test / Tool calling / Handoff tier — delete, keep connection test & auto capability fill only”；
诊断 M7 的决定 1 按推荐定为 “Delete them from the app and the spec; after a timeout Mori always waits 2 minutes before
switching”（本轮记录“按推荐定下的”）。诊断与计划在会话 scratchpad 的 `diag1.json`（M7）与 `plan1.json`（WP-04）。
界面上的两个按钮与确认框已由 WP-02 删掉；这包删后台进程里的第 8、9 步和只为它们存在的一切，改规格 §5.7 的超时处理。
在 `wt/wp04-remove-long-input-cancel` 分支上做（从本地 `app-v0` 的 10624c6 切出），不推送。WP-05 与这包并行，在这包之后合并。

**是 model-facing**：§5.7 发出后超时的处理变了（会话事件 `mori.model_wait`、`mori.model_switch`）。原来按档案的 `cancel_verified`
分三种：为真时记 `timeout`、立即换；为假时读服务端的进行中请求数、回到基线就换；为 `unknown` 时等满 2 分钟再换。现在只有最后一种。
负责人安装版的三个档案（deepseek-flash、glm-5.3、glm-5.3-flash）`longInput`、`cancel` 都是 null（复制一份档案文件读过，原文件没动），
`cancel_verified` 一直是 `unknown`，所以对负责人现在的模型超时处理没有变化；只有跑过取消测试的自建 vLLM、SGLang、llama.cpp 模型会变。
另外后台进程不再能发需要同意的长输入、取消探针请求（界面上 WP-02 起就没有入口）。

## 改了什么、为什么

| 原来 | 现在 |
| --- | --- |
| 探针第 0–9 步：第 8 步长输入（带暗号的长提示，填到有效窗口的 50%、90%），第 9 步取消（读 `/metrics` 或 `/slots` 的进行中请求数，发长输出请求、收到第一段就断开，5 秒后再读） | 只有自动的第 0–7 步（规格 §7.3） |
| `models.verify` 是 `{ refs, tests: 'auto' \| 'long_input' \| 'cancel' }` | `{ refs }`，跑第 0–7 步（§9.5）；模型行的 Verify again、拒绝启动卡的 Verify now 照旧发它 |
| 档案 `context` 有 `truncation`，静默截断时 `effective` 降到通过的长度；档案有 `cancel_verified` | `context` 是 `{ declared, reported, effective }`，`effective` 为声明与报告中较小的；没有 `cancel_verified`（§7.2） |
| `model-profiles.json` 的档案带 `longInput`、`cancel` | 不再写。旧文件里的这两项读的时候丢掉：`StoredProfileSchema` 是 `z.object`，不认识的字段**被剥掉、不是被拒绝**，档案其余各项照用、不重新探测，下一次写文件时不再写出；不加迁移（§7.2、MP-12） |
| §5.7 三种处理；`held` 期间每 5 秒读一次指标，回到基线就提前解除 `held` | 发出后超时：模型进入 `held`，等满 2 分钟再换，换模型提示注明 “Couldn’t confirm it stopped”（`unconfirmed`）；Mori 不读服务端，也不提前结束等待 |
| 时长 `heldPollMs`（5 秒）、`probeCancelMaxTokens`（2048）、`longInputFractions`（50%、90%）、`cancelProbeWindowMs`（5 秒） | 删掉。`timeoutCooldownMs`（60 秒）留着：压缩请求超时仍记 `timeout`（§6.4）；`heldMs`（2 分钟）照旧 |
| F8 报告的 Recent activity：`Verify <provider>/<id> (auto)` | `Verify <provider>/<id>`（`tests` 没有了） |
| 合成端点：`-truncate`、`-nocancel`、`GET /metrics`、`FAKE_NO_METRICS=1`、第 8 步的暗号回答、第 9 步的长输出 | 删掉；`/metrics` 现在同其他没有的接口一样是 404。`-hang`、`-stall` 照旧（MP-18 用） |

“结果未知”只剩一种，所以拒绝启动卡、阶段行与换模型提示的文字都没变：等待时阶段行照旧是
“Waiting to make sure <model> stopped · until hh:mm:ss”，换模型提示照旧是 “Switched model: A → B · … · Couldn’t confirm it stopped”。
