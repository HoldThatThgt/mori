# WP-00 自动找 Git Bash（M28）检查记录

依据：2026-10-26 负责人走查 M28（[../walkthrough-1026-checks.md](../walkthrough-1026-checks.md)），方案
[docs/app-v0.md](../../app-v0.md) 第 6 节"Shell"。分支 `wt/wp00-git-bash`，从本地 `app-v0`（`63cf4a9`）开出。

## 改了什么、为什么

负责人原话："bash not usable in mori"。

诊断（会话里直接核对的）：负责人三个会话里每次 bash 调用都报 pi 的 "No bash shell found"，模型只能一个个读文件，
还自己去 `System32`、`msys64`、`cygwin` 里找 bash。Git for Windows 装在 `D:\Git`，机器的 PATH 上只有 `D:\Git\cmd`
（只有 `git.exe`），`D:\Git\bin\bash.exe` 在；注册表 `HKLM\SOFTWARE\GitForWindows` 的 `InstallPath` 是 `D:\Git`。
pi 1.3.0 的 `getShellConfig`（`dist/utils/shell.js`）只看设置里的 `shellPath`、`%ProgramFiles%\Git\bin\bash.exe`
（及 x86 的）和 `where bash.exe`；负责人的 pi `settings.json` 里没有 `shellPath`。方案第 6 节写了"装在别处时给 pi
`shellPath`，没有 bash 时用 powershell"，一直没有实现。开发和打包测试都从 Git Bash 启动，继承了 `D:\Git\usr\bin`，
所以没有一个测试抓到。

现在：

- `app/src/kernel/shell.ts`（新）：后台进程每次启动查一次 bash（`findShell`，`index.ts` 收到 `start` 时就调）。
  用户级设置里已有 `shellPath`，或 pi 自己能找到（直接调 pi 导出的 `getShellConfig()`），就不动；否则对 `where git.exe`
  的每个结果按 `<Git>\cmd`、`<Git>\bin`、`<Git>\mingw64\bin` 推出 Git 的目录，用 `<Git>\bin\bash.exe`；
  再不行读注册表 `InstallPath`（先 HKLM 后 HKCU）。`where.exe`、`reg.exe` 用 `System32` 下的绝对路径。
  结果记一行英文日志，例如 `[kernel] shell: Git Bash D:\Git\bin\bash.exe (from git.exe on PATH), set as shellPath in memory`；
  哪里都没有时记错误 `[kernel] shell: no bash found (…); new sessions use powershell`。
- `app/src/kernel/pi.ts` `createSettingsManager`（新）：Mori 建的每一份 pi 设置都经它，建好后 `applyShell`：
  找到的 Git Bash 用 `applyOverrides({ shellPath })` 放进内存，没有 bash 时放 `defaultTools: ["-bash", "+powershell"]`；
  这份设置（用户级或受信任项目的）已有 `shellPath` 时两样都不放。pi 的 `save()` 只写改过的字段（`globalSettings` 的快照），
  所以你的 `settings.json` 不会被写进 `shellPath`。改用它的地方：`pi.ts` `globalSettings`、`sessions.ts` `createSettings`
  （用户会话与 Task mode 的实例会话）、`resources.ts` `resolveView` 与 `userPackages`（Customize）、`enhance.ts`
  `defaultThinking`、`mcpShare.ts` `userMcpEnabled`。`instances.ts`、`modelSession.ts` 不自己建设置（实例的设置来自
  `sessions.ts` 的 `createSettings`）。
- 已知问题 #9361（方案第 10 节）按 pi 1.3.0 源码复查：`DefaultResourceLoader.reload()` 会调 `settingsManager.reload()`，
  `SettingsManager` 的 `reload()`、`save()`、`setProjectTrusted()` 都按文件重新合并设置，`applyOverrides` 放进内存的值
  随之丢掉；bash 工具在 `AgentSession._buildRuntime`（建会话、`session.reload()` 时）取 `shellPath`，之后不再读。
  写在文件里的 `shellPath` 不受影响。所以 `sessions.ts` `loadResources` 在资源加载器 `reload()` 之后、`createAgentSession`
  之前再放一次。会话中途 pi 自己 `save()`（例如换思考强度）丢掉的覆盖不影响已建好的 bash 工具；Mori 不调 `session.reload()`，
  也不用 pi 的 `!` 命令（`executeBash` 每次重新读 `getShellPath()`）。
- 文档：方案第 6 节"Shell"改写为现在的做法，第 10 节第 6 条补了 #9361 的复查结论；临时默认值三条登记在
  [docs/v0/defaults.md](../../v0/defaults.md)（什么时候查、认哪几处 git.exe、`where`/`reg` 的时限）。
- 没有界面变化：没有新屏、状态、界面文字或测试标识（Claude 桌面版也不显示用的哪个 bash），状态表与
  [docs/v0/ui-strings.md](../../v0/ui-strings.md) 不用改。

## 按推荐替你定下的

1. 找法照轮次记录的决定：先 PATH 上的 `git.exe`（`<Git>\cmd\git.exe` 推出 `<Git>\bin\bash.exe`，另认 `bin`、
   `mingw64\bin` 两处），再看 Git for Windows 的注册表（HKLM 后 HKCU），找到只放内存、不写你的 `settings.json`。
   诊断计划里"在安装版数据目录的 `settings.json` 手写 `shellPath`"不做了（被这条取代），安装版的数据目录没有动。
2. 只在 pi 自己找不到时补：pi 找到的（包括 PATH 上的 WSL `System32\bash.exe`）不改成 Git Bash，照方案"靠 pi 自己的查找顺序"。
3. 设置里已有 `shellPath`（你自己写的，或受信任项目的 `.pi/settings.json`）时 Mori 什么都不放，包括没有 bash 时的 `defaultTools`。
4. 每一份 pi 设置都经 `createSettingsManager`，包括不跑 bash 的（Customize、MCP 启动检查、思考强度的读写）：这样各处
   `getShellPath()`、`getDefaultTools()` 读到的一样；WP-08 的内置工具开关要在 Customize 读同一份设置。
5. 每次启动查一次，之后复用；Mori 开着时装 Git 要重启（登记为临时默认值）。
6. `where`、`reg` 每次限 5 秒（同 pi），到时按没找到处理并记错误（临时默认值）。
7. git.exe 只认 `cmd`、`bin`、`mingw64\bin` 三处；ARM64 版的 `clangarm64\bin`、包管理器的 shim 跳过，接着看注册表（临时默认值）。
   32 位 Git 装在 64 位 Windows 上时注册表写在 `WOW6432Node` 下，没有读（这种情形 PATH 上的 `<Git>\cmd` 仍然能找到）。
8. 日志：找到（或 pi 自己能找到）记普通日志，没有 bash 记错误日志；界面上不提示。

## 交给后面的包

- WP-08（内置工具开关写 `defaultTools`）：没有 bash 时 Mori 在内存里加的是 `["-bash", "+powershell"]` 这样的修饰项，

  否则会把 Mori 在内存里加的当成你的选择写回去。
