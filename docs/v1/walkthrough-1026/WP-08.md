## 改了什么、为什么

负责人原话："why so many not-enabled tools? why can't I enable them?"；回答 3："Customize 的工具列表给 pi 的 8 个内置工具加开关
（存为 pi 的 `defaultTools`，对新会话生效），其余行写一行原因"。

诊断（复核过）：Customize 的内置工具一节列出会话注册的全部工具，只有状态、没有开关（代码注释写着"只读：v0 不在这里启停工具"）。
"Not enabled" 的行有两类：pi 总是注册、默认只启用 `read`、`bash`、`edit`、`write` 的另外 4 个（`powershell`、`grep`、`find`、`ls`），
和只在 Task mode 下启用的 TaskBoard 工具（负责人的项目只有基座，用户会话注册 9 个）。pi 用 `defaultTools` 设置选默认工具，
但 `SettingsManager` 只有 `getDefaultTools()`、没有写它的方法，Mori 也没有界面。另外 `grep`、`find` 要 rg、fd：Mori 让 pi 离线运行，
pi 不下载，负责人这台机器上也没有，打开了也会失败。

现在：

- **界面**（`ToolsBuiltin.tsx`）：pi 的 8 个内置工具每行右边一个开关（读屏名称 `Enable tool <名字>`，样子同技能、MCP 的开关），
  开着 = 新会话默认把它给模型；同一行的 `Enabled` / `Not enabled` 仍是这个会话的状态。标题下一行改为
  `All tools in this session. Only enabled tools are available to the model. Switches apply to new sessions.`（页面顶部原来就有
  `Changes apply to new sessions. Sessions already open aren’t affected.`）。`grep`、`find` 下面一行
  `Needs rg.exe in <agentDir>\bin or on PATH. Mori doesn’t download it.`（`find` 是 fd.exe，`<agentDir>` 写实际路径）。
  别的行没有开关，下面一行原因：TaskBoard 工具 `Mori turns this on and off with Task mode.`、`memory`
  `Mori turns this on for the main agent.`、MCP 的工具 `Turn its server on or off in MCP.`、插件的工具 `Turn it on or off in Plugins.`、
  扩展文件的工具 `Set by this extension. To change it, edit the extension file.`。写入失败时这一行下面 `Couldn’t save: <原文>`、
  开关回去；受信任项目的 `.pi/settings.json` 改了的工具开关不可用，下面一行同技能的
  `Turned on (off) in this project’s .pi/settings.json. To change it, edit that file.`。操作记录 `Enable tool <名字>` / `Disable tool <名字>`。
- **后台进程**：`tools.get` 的每个工具多一个 `byDefault`（pi 内置工具的开关状态与只读原因，别的工具为 null）；新命令
  `tools.setDefault { sessionId?, name, enabled }`。新文件 `kernel/defaultTools.ts`：照写 pi 1.3.0 选默认工具的三条规则
  （`resolveDefaultTools`、`mergeDefaultTools`、`getDefaultTools` 只认字符串；单元测试逐条对照 pi 真实的 `SettingsManager`），
  算出要写的 `defaultTools`，在 pi 自己的文件锁里读改写（见下面第 3 条）。`resources.ts` 读文件里的值（`getGlobalSettings()`、
  `getProjectSettings()`），按 WP-00 的交接不读 `getDefaultTools()`（它含 Mori 只放在内存里的 `-bash`、`+powershell`）。
  `PI_DEFAULT_TOOLS` 从 `sessions.ts` 挪到 `roles.ts`（与 `PI_TOOL_NAMES` 放在一起，两处共用）。这段非界面代码对应方案第 6 节
  "后台进程只做八件事"的第 1 件"读写配置"。
- **文档**：方案 5.13 与第 6 节"Shell"、[tools.md](../../v0/screens/tools.md)（内置工具的状态表重写：开关、按了开关、写入失败、
  本项目的设置、grep / find、别的行的原因，以及开关还管的几件事；"11 个 TaskBoard 工具"改为用户会话只注册的那一组：合并 9 个、
  分开 3 个；列表是上一轮运行时的样子）、[ui-strings.md](../../v0/ui-strings.md)、[defaults.md](../../v0/defaults.md)（三条）、
  [m6-checks.md](../../v0/m6-checks.md)（查的 pi 行为）、TaskBoard 规格 §6.3 与 TB-03、记忆规格 MEM-11、
  [memory-chat.md](../screens/memory-chat.md) 的工具页一行。

**发给模型的有变化**（所以要录 fixture、跑真实模型）：打开一个工具后，新会话发给模型的工具列表、system prompt 的 `<tools>`
与 `<rules>` 都随之变；打开 `grep`、`find`、`ls` 中任一个时 `<rules>` 不再有"Use bash for file operations like ls, rg, find"。
Task mode 的基座工具就是这些默认工具（`baseTools`），所以打开 `ls`、`grep`、`find` 也给了只读的助手（`readClassTools`），
没写 `tools` 的角色文件也跟着变（`roleTools`）。轮次记录定的"只读助手总有 `ls`"由 WP-10 做，这里只在 tools.md 写明规则。

## 按推荐替负责人定下的

1. 开关是"新会话的默认"，与同一行"这个会话 Enabled / Not enabled"分开显示；标题下一行加 `Switches apply to new sessions.`
   （诊断推荐的写法）。重启后重新打开的会话同样按新的设置（pi 在建会话时选默认工具），tools.md 写明。
2. 写法：按了开关先按 pi 的规则算出新会话的默认工具，整份写成相对 pi 默认（`read`、`bash`、`edit`、`write`）的差别，先 `-名字`
   后 `+名字`（例如 `["+ls"]`、`["-bash", "+powershell"]`）；与默认相同时去掉 `defaultTools` 这一项，从不写 `[]`（pi 把空列表当作
   一个工具都没有）。你手写的普通工具名写法按了开关后也改成这种写法，选出的工具不变（单元测试对每种写法、每个工具、开与关都核对过）。
   登记为临时默认值。
3. 写入的锁（简报要求记下选择）：用 pi 的 `FileSettingsStorage.withLock`（`dist/core/settings-manager.js`，没有从包的入口导出，
   按 pi 包里的文件路径载入，核对 pi 1.3.0，同 `mcpShare.ts` 的 `piPackageDir`）在锁里读出文件、只改 `defaultTools`、写回。
   pi 每个 setter 的保存（`persistScopedSettings`）在同一把锁里重新读文件、只合并它改过的字段，所以 Effort 默认
   （`modelThinkingLevels`，经 pi 的 `SettingsManager`）与这里交错也都不丢（单元测试用 pi 真实的 `SettingsManager` 核对）。
   没选的两种：`SettingsManager` 的私有成员（`globalSettings`、`markModified`、`save`）是先读后写，两次开关挨得近时后一次会盖掉
   前一次；Mori 的 `writeFileAtomic` 不拿 pi 的锁，会丢掉 pi 同时的保存。登记为临时默认值（pi 有了写 `defaultTools` 的方法就换）。
4. 开关只读写文件里的值（WP-00 的交接）。后果：完全没有 bash 时 Mori 只在内存里放 `-bash`、`+powershell`，那时 `bash` 的开关开着、
   新会话里它仍是 `Not enabled`；不加说明（WP-00 定了界面上不提示，这种机器很少），tools.md 写明。
5. 受信任项目的 `.pi/settings.json` 也写了 `defaultTools` 时，按工具比较"合并后"与"只按用户级"：不同的工具开关只读、显示合并后的样子，
   说明照搬技能的两句；相同的照常可以开关（同技能一节的做法，没有整节只读）。
6. 后台进程只接受 pi 的 8 个工具名（`PI_TOOL_NAMES`），只读的拒绝（`<名字> is read-only in Customize`，同资源的写法）。
7. `grep`、`find` 的说明总是显示、不检查程序在不在（pi 自己查要起进程）；写实际的 `<agentDir>\bin`。登记为临时默认值。
   不带 rg.exe、fd.exe（诊断第二个问题的推荐选项）。
8. 别的行的原因按上面五句；扩展文件的工具简报没提，同样没有开关，也给一句（用"To change it, edit …"的现成句式）。
   TaskBoard 的工具按名字认（`isTeamTool`），`memory` 按名字认（`toolTitle.ts` 的 `MEMORY_TOOL` 导出给它用），用 Task mode 的叫法。
9. 行的样子：保留 `<details>` 展开看完整说明，开关放在右边（CSS grid），说明占满下一行；行变淡仍按这个会话的状态，不按开关。
10. 操作记录写 `Enable tool <名字>` / `Disable tool <名字>`（同 `Enable skill <名字>`）。
11. TB-03 与没有 TaskBoard 的对照构建只比较 v0 起就有的五项（名字、启用、来源、状态、说明），另检查 8 个开关；规格 TB-03 加注。
12. `m6-app-tools.mjs` 加 `--only`（同 m2-app：`setup` 总是跑；其余步骤依赖前面的配置，只有 `entry` 能单独跑）。文件压在 1999 行。
13. 真实模型的用例放进 `m6-real.mjs` 的新一项 `t`（`--only t`；不带 `--only` 时也跑）。
