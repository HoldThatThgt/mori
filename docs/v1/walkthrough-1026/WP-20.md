## 替负责人按推荐定下的

1. **第一次关窗口的提示用托盘气泡**（`Tray.displayBalloon`，同 Claude），不做窗口里的提示：窗口已经藏起，窗口里的提示看不到。
   时机改成"第一次关窗口"（Claude 是"安装后第一次运行"）：Mori 没有安装后第一次运行的标记，而关窗口正是要说明的时刻；
   显示过后写空标记文件 `<userData>\tray-notice-shown`，以后（包括重启）不再弹。
2. **托盘菜单照 Claude 的 Windows 原样："Show App"、分隔线、"Exit"**，不用任务说明里举例的 "Quit Mori"（理由见上）。气泡正文
   "right-click to quit"、确认框 "Quit anyway" 里的 quit 也同 Claude。
3. **退出前确认在两个 "Exit" 上**（审查修正后）：托盘菜单的 "Exit" 和菜单栏的 File → Exit 走同一个 `confirmQuit`（同 Claude：
   它的 File → Exit 和托盘 Exit 是同一个守卫过的退出）。为此换掉了 Electron 的默认菜单（见决定 11）。确认放在两个菜单项的点击里，
   不放在 `before-quit` 里：界面测试用 Playwright 的 `app.close()`（直接 `app.quit()`）收尾，收尾时可能还有会话在生成，
   在 `before-quit` 里问会让收尾卡在确认框上；`app.close()` 仍不问、照样有序退出。Windows 注销、关机或重启时 Electron 不发
   `before-quit`、`will-quit`（Electron 对这两个事件的说明），所以那时既不问、也**没有**有序关闭：系统直接结束 Mori，
   后台进程和它的命令随作业对象一起结束（初版记录写成"照样有序退出"，是错的，审查指出后改正；没有实测）。
4. **确认框不做 "Wait for Mori"**：只有 "Quit anyway" 和 "Cancel"，默认 "Cancel"。"Wait for …" 要一个看不见的"等全部会话停下后自动退出"状态，
   等你批准或回答的会话会让它一直等。
5. **"正在生成的会话"用侧栏会话行的规则**（"Running"、"Needs approval"、"Needs input"，含界面重新加载后还没点开、仍在运行的），
   由界面推给主进程（数变了才发），主进程不来问、后台进程也不另算一份。
6. **窗口藏着时的批准提醒**：先 `minimize()`（窗口以最小化的样子回到任务栏，不抢焦点、不弹到前面）再 `flashFrame(true)`；不用系统通知。
7. **图标**是临时图标，只用在托盘（`Mori.exe`、窗口、任务栏仍是 Electron 默认图标）；放在 `src/main/assets/`（同界面的 `src/renderer/src/assets/`），
   不放任务里说的 `app/resources/` 或 `build/`：`resources/` 是 electron-vite 给主进程的 public 目录，构建时不复制进 `out/`，
   只复制 `out/` 的 `.tb-runs` 构建（`tb-build.mjs`）就找不到它；`build/` 是 electron-builder 的构建资源目录，不打进程序。
   打包时由 `asarUnpack` 放进 `app.asar.unpacked`，Windows 按路径读的是磁盘上的文件。
8. **单实例按数据目录**（Electron 的默认）：测试各用自己的 `MORI_USER_DATA`，互不影响；开发构建不设它时用 `%APPDATA%\Mori`，与安装版同一个目录，
   安装版开着时只会把安装版的窗口叫出来（以前会在同一个数据目录上开第二个 Mori）。
9. **有未保存的 AGENTS.md 改动时**：关窗口不丢（页面没关）；"Exit" 不为这件事问（同原来关窗口不问），只为正在生成的会话问。
10. **托盘的悬停说明 "Mori"**（Claude 用应用名）。
11. **应用菜单**（审查修正加）：换掉 Electron 的默认菜单，"File" 里只有 "Exit"（Claude 的 `EfdnINFnIz`、`7fdcqxofEs`），
    "Edit"、"View"、"Window" 用 Electron 的 `editMenu`、`viewMenu`、`windowMenu` 角色（项和快捷键同默认菜单，Ctrl+R、
    开发者工具、缩放都在）；Electron 默认的 "Help"（四个链接到 Electron 网站的项）不要了。
12. **增强任务不算"正在生成"**（审查修正时写明）：记忆的增强运行是看不见的会话，不在侧栏里，`busyCount` 不数它；
    增强正在运行时 "Exit" 不问、直接退出，这次运行下次启动时记为失败（"Mori closed during the run"），按 memory.md §9.10 重跑，
    已写入的改动可以回滚。关掉窗口不再中断增强（原来关窗口即退出），所以比原来少中断。要算进来见"需要你确认"第 4 条。

## 集成阶段要跑的

### 两个异常分支的用例（U10，临时默认值，不是状态表的行）

`tray.ts` 的两个 catch 原来列在"给负责人定的"里（第 2、3 条）。U10 按推荐定为照现在的做法，登记为
`docs/v0/defaults.md` 的两行临时默认值（"写不进第一次关窗口的标记文件"、"退出前的确认框弹不出来"），不写进状态表；
测试碰得到，所以在 `m2-app` 加了两步（不在快速集里），检查名是 `record` 的第一个参数：

| 临时默认值 | 用例（套件与 --only 名、检查名） |
| --- | --- |
| 写不进第一次关窗口的标记文件：记错误日志，之后每次关窗口都弹气泡 | **新加（集成时跑）**：`m2-app --only noticeUnwritable`"写不进标记文件时第一次关窗口（这次运行里）：窗口藏进托盘，照样弹气泡"Mori runs in the system tray"，记一条错误日志"cannot write …"，标记文件没有写下"、"写不进标记文件时第二次关窗口（这次运行里）：…"（同一句，第二次关窗口时气泡、写的尝试和错误日志都是 2） |
| 退出前的确认框弹不出来：记错误日志，"Exit"什么都不做 | **新加（集成时跑）**：`m2-app --only exitNoDialog`"有会话在生成时点托盘"Exit"、确认框弹不出来：记一条错误日志"cannot ask before quitting"，什么都不做——Mori 不退出，窗口和托盘图标都在，回复照常生成" |

怎样碰到（只在测试里做，`src/` 没有改动、没有给测试用的入口；两处换掉的函数都标 synthetic）：

- 标记文件写不进：lead 的说明里举的办法"在数据目录里先建一个名为 `tray-notice-shown` 的目录"碰不到这个分支：`noticeOnce` 先
  `existsSync(marker)`，目录也算存在，于是当作"已经提示过"，既不弹气泡也不写，测到的是另一个分支。要碰到 catch，路径必须不存在、
  写的时候又失败。没有改数据目录的权限（Chromium 自己的 `Local State`、`Preferences` 也写在数据目录的根上，拒绝在那里建文件会连带
  它们）；`noticeUnwritable` 在主进程里（`app.evaluate`）把 `node:fs` 的 `writeFileSync` 换成只对文件名是 `tray-notice-shown` 的路径
  抛出 EPERM（同 Node 写不进文件时的错误）、别的文件照常写的版本，并数这样的尝试（`tray-helpers.mjs` 的 `failMarkerWrites`、
  `markerAttempts`、`restoreMarkerWrites`）。Mori 的主进程构建成 CommonJS（`out/main/index.js` 里是 `node_fs.writeFileSync(marker, "")`，
  `node_fs = require("node:fs")`），换掉这个对象上的方法就换到了它；没换上时标记文件会写下、尝试次数是 0，检查失败。这一步要在
  这次运行第一次关窗口之前（`steps` 里排在 `hiddenFlash` 前面；只跑 `--only noticeUnwritable` 时前面只有 `setup`，也不关窗口），
  检查里另查开始时标记文件不存在。关窗口、点托盘图标回来、再关一次；气泡照 `recordBalloons` 只记参数不弹出。结束时换回原来的
  `writeFileSync`，后面 `hiddenFlash` 第一次关窗口照常写下标记文件。
- 确认框弹不出来：不需要 `tray-hook.cjs`（lead 的说明里提的办法）：`confirmQuit` 调用时才读 `dialog.showMessageBox`，`exitNoDialog` 在主进程里
  把它换成"这一次返回失败的 Promise，同时换回原来的"版本（`failMessageBoxOnce`、`restoreMessageBox`），开发构建和打包程序（`--exe`，
  不认 `-r`）都能用。先让当前会话生成（"wait 8s"，等 `data-running` 和 500 毫秒让界面报告的数到主进程），再点托盘"Exit"；
  失败次数是 1 说明走到了确认框（数为 0 时会直接退出，那时检查失败）。1.5 秒后查进程没退出、托盘和它的菜单还在、窗口仍在桌面上、
  这个会话仍在生成。
- 错误日志：主进程的 `console.error` 写在它的标准错误里，`m2-app` 启动后收集（`collectMainLog`），按这一步开始时的位置往后数
  `[main] cannot write …tray-notice-shown: `、`[main] cannot ask before quitting: ` 出现的次数（`waitLogCount`，最多等 3 秒）。

### 不能自动测的（负责人走查）

1. 托盘图标的样子（`tray.ico` 在真实托盘里，100% / 150% / 200% 缩放、深色和浅色任务栏）：要人看，测试读不到系统托盘画出来的图标。
2. 打包程序（`--exe`）上的悬停说明与右键菜单：Playwright 对打包程序不加 `-r`，打包程序也不经 default_app、不认 `-r`，钩子载不进去，
   `Tray` 又没有读取接口；这两项只在开发构建上查（`m0-smoke --exe` 打印一行 NOTE，不记检查）。打包程序用的是同一份 `tray.ts`。
3. 托盘菜单"Esc 或点别处关上菜单"：这是 Windows 原生弹出菜单自己的行为；测试经 `Menu` 对象直接调菜单项的 `click()`，
   打开原生菜单要真实的鼠标、键盘输入到系统的菜单窗口，界面测试碰不到。
4. 第一次关窗口的气泡作为 Windows 系统通知的样子、文字是否完整：测试把 `displayBalloon` 换成只记参数（真弹会在测试机上留下通知），
   参数全等已断言。
5. 打开窗口后窗口真的拿到前台焦点（`isFocused`）：Windows 的前台锁规则，测试进程不在前台时不交焦点；测试断言调用了 `focus`。
6. Windows 注销、关机或重启时不问、没有有序关闭（U6，`window.md` 表下"其他退出的方式"）：要真的注销或关掉这台机器，界面测试做不到。
