# WP-21 不留未完成项、不做规格外的东西：规则与检查

负责人 2026-10-26 的要求（原话）："Do not defer any pending implementation work — enforce this with test cases — and do not
build anything the spec doesn't describe."（对 lead 和所有子会话。）

## 改了什么

- `AGENTS.md` 加一节"不留未完成项，不做规格外的东西"：规格写了的在同一个包、同一个会话里做完；等别的包的部分那个包一合并就做，
  不依赖的现在就做；要负责人选的先按推荐做完并登记临时默认值；先写规格、再写测试、再实现；规格外的不做。
- 单元报告器全部严格模式：`tb-reporter.mjs`、`mem-reporter.mjs` 原来不严格（跳过的、标为待办的测试记为通过），现在同
  `reporter.mjs`、`md-reporter.mjs` 一样算失败。工厂 `createReporter` 去掉 `strict` 参数，不留不严格的写法；
  `spec-coverage.test.mjs` 里"不严格时照旧"的测试随之删掉。
- 新检查 `tests/unit/spec-ids.test.mjs`（在 `npm run test:unit` 里，每次改动都跑）：每份规格（`SPECS` 的 model、taskboard、
  memory、discovery）验收表的每个编号，在它列出的每一层都有测试写好（`app/tests` 下有字符串字面量以这个编号开头，按文件认层）；
  测试里用到的编号都在表里。只读源码，不启动 Mori。
- `tests/spec-coverage.mjs`（推送前）：名字以这份规格的前缀开头、编号却不在验收表里的检查，原来只列出，现在算缺口
  （`unknownIdChecks`）；不以编号开头的检查照旧只列出（`strayChecks(spec, files)`）。

## 现状

在本地 `app-v0`（`2c05118`）上：四份规格 150 个编号，每个编号列出的每一层都已有测试；测试里没有表外的编号（覆盖检查自己的单元测试
用的 `TB-010`、`TB-460`、`MD-99` 是编造的，不算）。现有的单元测试里没有跳过的或标为待办的，改成严格模式后结果不变。

## 跳过的层

- 快速集与界面用例：只改了 `app/tests` 下的测试工具和文档，`src/` 没动，界面套件不用这几个文件（它们用 `tests/ui/lib.mjs` 的
  记录器）；写这包时第二波的集成正占着测试端口。之后每个包的集成照常跑快速集，都在这包之上。
- 真实模型、fixture、打包：不涉及。
- 覆盖检查的整套（`spec-coverage --spec …`）按测试分层第 3 条在推送前跑；它的单元测试已在 `test:tb-unit` 里通过。

## 审查之后改的（2026-10-26，第二次提交）

独立审查（只读，在临时副本上复现）找出的问题和改法：

| 问题 | 改法 |
| --- | --- |
| high：spec-ids 按文件名猜层，不管测试的结果写进哪份规格的结果文件，例如 `MEM-39` 写在 `tests/unit/taskboard/` 也算记忆的单元层、`m0-smoke` 记的 `MP-41` 算 App 层、`tb-record.mjs` 的 `covers` 也算；推送前的覆盖检查却找不到 | 层按覆盖检查认结果文件的办法认：`SPECS` 每份加 `unitGlob`，单元层只认那个目录（不往下一层）；`tests/ui/` 的脚本按“脚本名.json”交给 `layerOfFile`，`*-helpers.mjs` 不算；`v1-models-existing.mjs` 算 App 与回放 |
| medium：注释里的编号也算（例如 `sa-reporter.mjs` 注释里的 "SA-03 …" 让 SA-03 算有单元测试；删掉一行后旧注释里的编号让反向检查失败） | 字面量从 TypeScript 的语法树里取（字符串、没有插值的模板字符串、模板字符串开头一段），注释不在语法树里 |
| medium（流程）：验收表加了行、测试还没写的分支合进 `app-v0` 会让每个包的 `test:unit` 失败 | AGENTS.md：新行和它的测试同一次合并 |
| 规格加进 `SPECS` 不等于推送前会跑它的覆盖检查 | spec-ids 第三项：`package.json` 有脚本用写 `files.unit` 的报告器跑 `unitGlob`、有脚本跑 `spec-coverage --spec <名字>`、用到这份规格编号的 App 和回放套件都在某个脚本里 |
| AGENTS.md 的措辞（a–h）：等别的包的部分谁做、算不算完成；包说明能不能比规格多；“按推荐做”与“问负责人”的分界；md-markers 查不到的；`known` 的现有误用；按屏规格做的包没有验收表；新规格要接进脚本；包里的“通过”指什么 | 重写这一节：分成做完、不做规格外的、用测试守住、机器查不到的四条，逐项写明 |
| `known` 被用来放过自己没做完的：`m6-replay.mjs` 的 thinking、tool-switch 在 fixture 还没录时记 KNOWN | 改为记失败（两段现在都走不到：fixture 已经录了） |
| `spec-ids.test.mjs` 有一行 121 个字符 | 改短 |

审查另外说的、没改的：`tests/unit/discovery/profile-step0.test.mjs` 里四个以 `MP-10`、`MP-12` 命名的测试写进 `md-unit.json`，模型层的覆盖
检查读不到、一键拉取模型的只列出；它们照样由 `test:md-unit` 的退出码把关，改名要动一键拉取模型规格的条目，这包不做（规格外）。
`spec-coverage.test.mjs` 写死了四份表的行数（57、40、38、15），加行的包要一起改，这是原有的做法。
