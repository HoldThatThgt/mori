# WP-21 不留未完成项、不做规格外的东西：规则与检查

负责人 2026-10-26 的要求（原话）："Do not defer any pending implementation work — enforce this with test cases — and do not
build anything the spec doesn't describe."（对 lead 和所有子会话。）

## 改了什么

- `AGENTS.md` 加一节"不留未完成项，不做规格外的东西"：规格写了的在同一个包、同一个会话里做完；等别的包的部分那个包一合并就做，
  不依赖的现在就做；要负责人选的先按推荐做完并登记临时默认值；先写规格、再写测试、再实现；规格外的不做。
- 单元报告器全部严格模式：`tb-reporter.mjs`、`mem-reporter.mjs` 原来不严格（跳过的、标为待办的测试记为通过），现在同
  `reporter.mjs`、`md-reporter.mjs` 一样算失败。工厂 `createReporter` 去掉 `strict` 参数，不留不严格的写法；
  `spec-coverage.test.mjs` 里"不严格时照旧"的测试随之删掉。
- 新检查 `tests/unit/spec-ids.test.mjs`（在 `npm run test:unit` 里，每次改动都跑）：每份规格（`SPECS` 的 model、taskboard、
  memory、discovery）验收表的每个编号，在它列出的每一层都有测试写好（`app/tests` 下有字符串字面量以这个编号开头，按文件认层）；
  测试里用到的编号都在表里。只读源码，不启动 Mori。
- `tests/spec-coverage.mjs`（推送前）：名字以这份规格的前缀开头、编号却不在验收表里的检查，原来只列出，现在算缺口
  （`unknownIdChecks`）；不以编号开头的检查照旧只列出（`strayChecks(spec, files)`）。

## 现状

在本地 `app-v0`（`2c05118`）上：四份规格 150 个编号，每个编号列出的每一层都已有测试；测试里没有表外的编号（覆盖检查自己的单元测试
用的 `TB-010`、`TB-460`、`MD-99` 是编造的，不算）。现有的单元测试里没有跳过的或标为待办的，改成严格模式后结果不变。

### 模型看到的变化：为什么没有真实模型走查、没有重录

上表“也给模型”的文字，模型看到的是同一句话里一个字符从 ' 换成 ’（工具的说明、工具结果、交给立项的问题和交接原因）；
工具名、参数、schema、顺序和程序的判断都没变。测试分层第 5 条要求模型看到的有变化时跑覆盖它的真实用例、录 fixture，这次没有做：
这台机器没有带 key 的数据目录（`mem-real.mjs` 开头写明），真实套件要负责人的数据目录（`--source`），负责人不在。各条路径：

- 工具的说明：每次真实运行都会发出去，但真实用例只断言程序保证的事，看不出这个字符。最省的是
  `node tests/ui/tb-real.mjs --source <数据目录> --only approval`（一个 /task、一条命令：每个 TaskBoard 会话都有 `read_session`，
  立项会话有 `request_submit`、`request_update`、`task_edit`）和 `node tests/ui/mem-real.mjs --source <数据目录> --only dialog`
  （memory 的说明随每次请求发出）。
