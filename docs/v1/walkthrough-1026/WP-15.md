## 负责人的原话

回答 1：“模型列表只给名字时（z.ai），上下文窗口、最大输出和是否支持思考**按服务地址从 pi 自带的模型表取**（api.z.ai 取 z.ai 的条目），
不按模型名猜；仍是猜的值标 "(default)"。这推翻了 2026-10-23 的“不用 pi 的模型表”……两处要先改（WP-15）。”

背景（诊断）：z.ai 的列表（`glm-models-1.json`，2026-10-24 录）每行只有 id、display_name、type、created_at，所以拉取时 GLM 各模型都是
128,000 / 16,384、思考不勾；负责人后来手改成 1,048,576 / 131,072、勾了思考，之前 z.ai 拒绝过更大的 max_tokens（“range [1,131072]”）。
pi-ai 1.3.0 的模型表里 Z.AI 的 glm-5.3、glm-5.3-flash 都是 1,000,000 / 131,072、支持思考。

## 改了什么

**给模型看的（model-facing）**：发给模型的上下文窗口与 max_tokens 来自配置；拉取模型时 z.ai 这类只给名字的列表，pi 认得地址的模型现在
加入时就是 pi 的值（glm-5.3：1,000,000 / 131,072、Supports thinking），不再是 128,000 / 16,384、不勾思考。已有的配置不自动改。

**拉取（规格 §4.4、§5.2）**

- 新的 `kernel/piCatalog.ts`：pi 没有“地址 → 提供商”的查询（它按地址调整请求时，`openai-completions.js` 的 `detectCompat` 看的也是
  `baseUrl` 里的主机），所以用 `@earendil-works/pi-ai/providers/all` 的 `builtinProviders()`，按每个聊天模型条目自己的 `baseUrl` 的
  origin 建一次索引（origin → id → 条目），`catalogEntry(baseUrl, modelId)` 按“同一个 origin、id 完全相同”查。pi-coding-agent 的
  `model-runtime.js` 本来就 import 这个模块，后台进程里不多载入东西；索引在第一次查时建一次（`builtinProviders()` 在本机约 4 ms），之后只查。
  （集成时改：静态 import 让后台进程起不来，改成 `loadCatalog()` 动态加载、加载时建索引，见“集成”第 2 条。）
- `discoverRead.ts`：`CatalogEntry`、纯函数 `fromCatalog`（只取服务没报告的项：窗口；最大输出小于这一行的窗口时；思考为真时）；
  `readRow` 多一个参数（服务没报告窗口时，“不小于窗口的输出上限不算报告”按 pi 的窗口比）；`finalizeModel` 先用服务的值、再用 pi 的、
  最后默认值，`reported` 不变，另记 `catalog`（取了哪几项、pi 的提供商名）。
- `modelDiscover.ts`：`buildModels` 对每一行查一次（命令与第 0 步的单模型模式都经它）。第 0 步记进档案的 `reported`、`meta` 仍只有服务的值。
- `shared/models.ts`：`CatalogValues`；`DiscoveredModel.catalog`；`ProfileView.catalog`。

**档案视图（规格 §7.2）**：`modelProfiles.ts` 的 `catalogOf` 在拼 `ProfileView` 时按配置的地址与 id 查（集成时改：条目由模型层查好
传给 `profileView`，见“集成”第 2 条），只取第 0 步没读到的项（同一个
`fromCatalog`），不写进 `model-profiles.json`；旧档案（没有 `meta`）与还没有档案时为 null。有效窗口不变（配置与服务报告中较小的）。

**界面（规格 §6.2、§8；状态表 models-settings.md、first-run.md）**

- 清单：取自 pi 的 Context window、Max output（框里的值仍等于它时）与 Supports thinking（仍勾着时）旁边写“From pi”，悬停
  “The server didn’t report this, so Mori used pi’s model list for Z.AI. Change it if you know the real value.”；改窗口时没改过的 Max output
  先看服务报告的、再看 pi 的、最后默认值。“From pi”与“Default”不同时写。手填的行不查。
- 模型行：数字后面与“Supports thinking”后面“ (from pi)”，悬停“… Use Edit to set the real value.”；配置仍是 Mori 默认值的模型多三条提示和 Use：
  “pi’s model list for <provider> has a context window of <N>.”“… has max output of <N>.”“… says this model supports thinking.”；
  “This model returned thinking content.”在 pi 的思考提示出现时不出。
- 规则从 `ModelRows.tsx` 移到纯函数文件 `settings/modelHints.ts`（`valueMarks`、`modelHints`、`piRowTitle`），单元测试直接测；
  `thousands` 从 `common.tsx` 移到纯函数文件 `settings/format.ts`（`modelHints.ts` 不必载入 React 组件；`AgentsSection.tsx`、
  `MemoryAgent.tsx` 改 import）。样式 `.pi-value` 同 `.default-value`。
