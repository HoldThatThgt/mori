## 改了什么、为什么

### M10：开关从顶栏进模型菜单

- 顶栏的协作开关（`role="switch"`，`Team: Off` / `Team: On` / `Team: Until done`）和不宽于 600px 时的状态点整个去掉
  （`ChatPane.tsx` 的 `<TeamSwitch>`、`team.css` 的开关与窄栏样式、`defaults.md` 的“协作开关的窄栏宽度”、TB-53 的窄栏一条）。
  顶栏现在只有“项目名 › 会话名”、“Toggle changes”和分屏时的“Close pane”。
- 模型菜单（输入框下面一行的模型按钮打开的那个）加一行 `Task mode`：`role="menuitemcheckbox"`，`aria-checked` 在 `once`、`always`
  时为真，右边画一个开关的样子（复用 Customize 的 `.tools-switch` 外观，不另算控件）；打开时第二行小字 `Messages go to <create role> first`
  （一直打开）或 `Until done · Ends when open requests are done`（做完为止），也是读屏的描述。点击、Enter、Space 的规则不变
  （`toggleTeam`），不确认，菜单不关、焦点留在这一行。位置：范围的几节和说明之下、`Manage models` 之上（Claude 的 Fast mode
  也是模型菜单里的一行，`Toggle Fast mode from the model picker`）。测试标识沿用 `data-testid="team-switch"`、`data-mode`。
- 协作模式下（`pickLocked`）模型按钮不再是没有菜单的锁定按钮：照样有 ▾、能打开菜单，菜单里没有 Groups / Providers / Models，
  换成说明 `Task mode picks the model for each agent`，下面是 Task mode 一行和 `Manage models`。菜单的几部分位置固定，
  三节换成说明时 Task mode 一行还是同一个元素，焦点不丢。
- 不打开菜单也看得出模式：协作模式下（`TeamState.mode` 不为 `off`）模型按钮显示 `Task mode · <当前模型 id>`
  （没有当前模型时只有 `Task mode`），读屏名 `Model: Task mode, <模型 id>`，悬停第二行 `Task mode picks the model for each agent`；
  按钮带 `data-team-mode`，`pickLocked` 时带 `data-locked="true"`。截短照范围按钮：先截模型 id，再截 `Task mode`。
- 回复进行中（准备中、生成中）模型按钮不再 `aria-disabled`，菜单能打开：三节的项照常列出但 `disabled`（↑ ↓ 跳过），说明换成
  `Can’t switch models until the response finishes`，Task mode 一行照常能切（§13.1 本来就允许回复中切，只影响之后的消息）。
  悬停第三行和读屏的描述仍写这句原因。菜单开着时回复开始，菜单不关，焦点从变得不可用的项移到 Task mode 一行
  （`useBusyRefocus`）。只有界面没准备好（`unavailable`）和换范围、换强度还没返回时按钮不可用、菜单打不开。
- 切换失败 `Couldn’t change task mode: <原文>`：菜单开着时在 Task mode 一行下面（`TeamErrorNote`），关着时（例如 `/team on` 失败）
  从输入框下面一行往上弹出（`TeamErrorLine`，同换范围失败）；10 秒后或下次切换时消失。
- 走查 2 的 Shift+Tab：从新会话的输入框回会话树从 6 次变回 5 次（右栏开关 → 左栏分隔线 → 底部两个按钮 → 会话行）。

### M21：界面上的 “team mode” 改成 “Task mode”

只改人看的文字；命令 `/team` 和发给 agent 的文字（工作卡、附加段、工具说明、`RELAY_ONLY`、`board_read` 的头）留给 WP-10。
代码里的名字（`TeamMode`、`TeamSwitch`、`session.setTeam`、`mori.team_*`、测试标识 `team-switch`、`stop-team`）不变，
`session.setTeam` 和会话事件都没变。

| 位置 | 原来 | 现在 |
| --- | --- | --- |
| 开关 | `Team: Off` / `Team: On` / `Team: Until done`，悬停 `Turn on team mode` 等 | 模型菜单里的 `Task mode` 一行（上面） |
| 模型按钮（协作模式） | 只有模型 id，悬停 `Team mode picks the model for each agent` | `Task mode · <模型 id>`，悬停第二行 `Task mode picks the model for each agent` |
| `session.setPick` 被拒绝的原文（`modelSession.ts`） | `Team mode picks the model for each agent` | `Task mode picks the model for each agent` |
| 拒绝启动卡、No model available 卡 | `Turn off team mode` | `Turn off task mode` |
| 输入框旁的按钮 | `Stop team` | `Stop agents`（悬停 `Stop all agents in this session` 不变） |
| 右栏说明 | `Changes made by team tasks aren’t listed here.` | `Changes made by other agents aren’t listed here.`（与 subagent 规格 §7.6 同一句） |
| 增强设置对话框 | 分组 `Team mode`、勾选框 `Run with team mode` | `Task mode`、`Run in task mode` |
| F8 的 Recent activity | `Team on` / `Team off`、`Send (team): …`、`Stop team` | `Task mode on` / `Task mode off`、`Send (task mode): …`、`Stop agents` |
| 记忆页里打不开的会话 | `This is a team task’s session, which can’t be opened.` | `This is a background agent’s session, which can’t be opened.` |
| 会话打不开的横幅（`sessions.ts`） | `The team extension failed to load: …` | `The TaskBoard extension failed to load: …` |

内核里提到按钮名的注释一起改成 `Stop agents`；内核日志 `Stop team dropped a delivery` 是日志，不改（`tb-app-stop` 按它查）。

## 按推荐替负责人定下的（负责人没单独回答）

1. 模型按钮上写字 `Task mode · <模型 id>`（M10 决定 1 的推荐；另两个选项：图标加悬停、按钮上什么都不写）。
2. 回复进行中模型菜单能打开，模型的项变灰，Task mode 照样能切（M10 决定 2 的推荐；另一个选项：回复中只能用命令切）。
3. `Stop team` 改为 `Stop agents`（M21 决定 3 的推荐；另一个选项 `Stop tasks`：这个按钮也停对话、立项、结案和临时提问，不只是 task）。
4. 右栏说明用 `Changes made by other agents aren’t listed here.`（任务说明里与 subagent 规格约定的写法；诊断原来写的是 `… by tasks …`）。
5. 记忆页那句改为 `This is a background agent’s session, which can’t be opened.`（诊断的建议：实例会话也可能是立项、结案、临时提问的）。
6. 会话打不开的横幅叫 `TaskBoard extension`（诊断的建议）。

## 实现时定下的（临时，走查时可以改）

- 菜单的顺序：范围的三节 → 说明 → Task mode 一行（和切换失败的一行）→ `Manage models`。诊断写的是“Task mode 在说明之上”；
  说明讲的是范围，所以放在三节下面，Task mode 自成一组（上面一条分隔线）。customize-agents 规格要在 Task mode 一行下面加
  `Manage agents`（它的 §6.6），这个位置留给它：`.task-mode-group` 里 Task mode 一行之后、`Manage models` 之前。
- 协作模式的菜单把说明 `Task mode picks the model for each agent` 放在原来说明的位置（`data-testid="model-menu-note"`，三种文字共用一个元素）；
  customize-agents 规格 §6.6 写“模型那一节变灰、悬停 …”，这里按 WP-09 的任务说明做成只有说明，合并它时照这里改一句即可。
- `off` 时 Task mode 一行没有第二行（不写 `Turn on task mode`）；`once` 的第二行 `Until done · Ends when open requests are done`。
- 点了 Task mode 一行菜单不关、焦点留在这一行；切换中这一行 `aria-disabled`、`data-pending`，保持原来的样子（审查之后改，原来是 `disabled`，
  见“审查意见与处理”第 1 条）。
- 模型按钮上的 `Task mode` 跟着 `TeamState.mode`，不等 `pickLocked`：回复中打开 Task mode，按钮马上是 `Task mode · <这一段的模型>`，
  菜单里的三节要到这次回复结束、`pickLocked` 变为真时才换成说明（§5.1：正在进行的回合按它开始时的模式跑完）。
- 协作模式下没有当前模型时按钮只写 `Task mode`（原来写 `No model`）。
- 协作模式的按钮悬停不加 `Can’t switch models …`（原来锁定按钮也不加）；界面没准备好时第三行是原因。
- 回复进行中范围的项用 `disabled`（不是藏起来），这样 ↑ ↓ 跳过它们、打勾照旧看得见。
- `agents_invalid` 时 Task mode 一行不可用，没有另加说明（拒绝启动卡就在上面）。
- 协作模式的菜单里说明是第一项，上面不画分隔线（集成时截图看到多出一条线后定的，model-menu.md“协作模式的菜单”）。
