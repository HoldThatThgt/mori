## 改了什么、为什么

设置 → Models 有三种列表靠同一对上移、下移箭头按钮排序（`common.tsx` 的 `MoveButtons`）：提供商卡里的 Models（范围与分组展开的
顺序）、Keys（key 的使用顺序）、分组的成员（候选顺序）。移三格要点三次、写三次配置、编译三次。现在三种列表都改成拖动：

- **柄**：有两行以上时每行左端一个拖动柄（六个点的图标，淡色，悬停变深，鼠标是抓手）；读屏名“Reorder <名字>”，悬停
  “Drag or use the arrow keys to reorder”，都是 Claude 桌面版的原词（`ion-dist/i18n/en-US.json` 的 `VUhJNoYJ96`、`f1bTS9DRGd`）。
  名字：模型行是模型 id，key 行是 key 的标签，成员是成员的写法、读屏名里“ · ”换成“, ”（“Reorder Local A, all models”，
  ui-strings 写法约定：读屏名里不用“ · ”）。只有一行的列表没有柄。上移、下移按钮整个删掉。
- **鼠标**：按住柄拖，整行跟着走，原来那一行变淡；鼠标在同一个列表别的行的上半边插在它前面、下半边插在它后面，那一行上沿或下沿
  一条强调色的线；放下后顺序不变的位置没有线、不能放下。只能放在同一个列表里（私有的拖放类型 `application/x-mori-reorder`
  加列表标识；`SessionDrag.tsx` 的整窗监听只认它自己的类型，互不干扰）。
- **键盘**：焦点在柄上按上、下方向键，这一行移一格并立即保存，焦点留在这一行的柄上（行换了位置也是）；第一行按上、最后一行
  按下不发命令。
- **保存**：一次放下或一次方向键只发一条命令：Models `models.moveModel`、Keys `models.moveKey`（`delta` = 新位置 − 原位置，
  例如把第三行拖到第一行是 -2），分组 `models.saveGroup`（新的成员顺序）。保存中列表按新顺序显示、柄不响应；失败时回到原顺序，
  原文在这个列表下面（Models、Keys 原来在那一行里，分组同它别的改动）。成功后读屏播报“<名字> was dropped at position <n> of
  <count>.”（Claude 的 `ZahmLApCvz`，`role="status"` 的区域，屏幕上不显示）。
- **命令**：`models.moveModel`、`models.moveKey` 的 `delta` 从 `-1 | 1` 放宽为不等于 0 的整数，名字不变；后台进程的 `moved`
  从“和邻居换位”改成“拿出来插到新位置”（`shared/models.ts` 新的 `movedItems`，界面算保存中的新顺序也用它），移出列表时照旧报
  “Cannot move <name> further”。一次放下一次写入、一次编译。操作记录的写法不变（“Move model <provider>/<id> <delta>”，现在可以是 -2）。

## 按推荐替负责人定下的

负责人没单独回答，按诊断的推荐（本轮记录“按推荐定下的”一节的总则）和任务说明定，都登记在 `docs/v1/defaults.md`“拖动排序”：

1. 三种列表（Models、Keys、分组成员）都改拖动（诊断的决定 1 推荐“All three”；key 的顺序就是使用顺序，同样要排）。
2. 柄在行的左端（原来箭头在右边的按钮里）；只有一行时没有柄（原来第一行没有上移、最后一行没有下移，一行时两个都没有）。
3. 键盘：上、下方向键一次移一格就保存，焦点留在柄上；不做 Claude 的完整键盘模式（按空格拿起、方向键移动、空格放下、Esc 放回，
   四句播报）。诊断复核时就简化成这样；Claude 的“Drag or use the arrow keys to reorder”正好说的是这种用法。
4. 读屏名、悬停与播报都用 Claude 的原词；播报只用“… was dropped at position … of ….”（拖动和方向键都在保存成功后播），
   Claude 的“Picked up …”“… will move to …”“Reordering … was cancelled …”没有用到（没有拿起状态）。
5. 成员的读屏名与播报里“ · ”换成“, ”（ui-strings 写法约定）；屏幕上的写法不变。
6. 放下的位置按行的上半边、下半边算；顺序不变的位置不显示线、不接受放下；线是 2px 的强调色（`--color-accent`），被拖的行
   不透明度 0.45，拖着的影子是整行（`setDragImage`）。
7. 保存中柄用 `aria-disabled`、不能拖、方向键不动，不设 `disabled`（设了焦点会丢，方向键连按时焦点跑到页面上）。
8. Models、Keys 的移动改为整张列表一个保存状态（同分组原来的做法：保存中显示新顺序），失败的原文因此在列表下面，不在那一行里。
9. 桥：保留命令名和 `delta`，只放宽取值（不改成 `to`），操作记录、回放桥的命令列表、`v1-models-app-switch.mjs` 里
   `delta: -1` 的调用都不用改。
10. 行的布局：按钮靠右，柄与行的文字靠左。Keys 的“Saved”和记录因此紧跟在标签后面（原来 `space-between` 把它们分散在一行里）。
11. 测试：新用例放进新套件 `v1-models-app-reorder.mjs`，不放进 `v1-models-app-settings.mjs`（它已到 2000 行的上限，排序又要自己的
    三行列表）；端口 4944（本轮各包用 4920–4949，4936 已被 WP-08 的 `m6-app-tool-switches.mjs` 占用）。
12. “一次放下一条命令”的 App 侧证据用 F8 报告的操作记录（渲染进程每发一条命令记一行），不另加测试钩子。
13. MP-24 的层加上“单元”（它原来就有四条名字以 MP-24 开头的单元测试，现在条目里写明单元层查什么）。
