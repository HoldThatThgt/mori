## 改了什么、为什么

负责人要 Claude 那样的上下文分项。原来圆环的详情只有"Context window"一行和一条圆环颜色的 4px 进度条
（`UsageRing.tsx` 的 `UsageDetails`），后台进程只给 pi 的 `{ tokens, contextWindow, percent }`，算不出分项。

- 后台进程（方案第 6 节第 1 件事：调用 pi、读会话的状态）：新的 `kernel/contextBreakdown.ts`（纯函数）按状态表分项；
  `sessions.ts` 的 `contextState` 在 `session.state` 和会话信息里一起给出 `contextUsage` 与 `contextBreakdown`。输入都取自 pi：
  - 当前提示词：`entry.model.piAi.getCurrentSystemMessage(session.messages)`（pi-ai 重放会话里每一条 system 消息，分节按名字
    替换、null 删掉，工具按增删算出当前的），不自己写重放；
  - MCP 工具：`session.getAllTools()` 里 `sourceInfo.path` 为 `builtin:mcp` 的。这个判断原来是 `resources.ts` 里的私有常量，
    挪到 `mcpConfig.ts` 导出成 `isMcpTool`，工具页和分项共用（不放在 `resources.ts`：它 import 了 `sessions.ts`，会成环）；
  - 自动压缩留出的数：`session.settingsManager.getCompactionSettings(session.model)`，与 pi `_checkCompaction`
    （agent-session.js:2363）的调用相同，项目 `.pi/settings.json` 改了也跟着变；
  - 用量：`session.getContextUsage()`。
- 协议：`shared/protocol.ts` 加 `ContextBreakdown`，`SessionInfo`、`SessionState` 加 `contextBreakdown`。
- 界面：`UsageRing.tsx` 的详情在第一行下面画分段条（`data-testid="usage-bar"`、每段 `usage-segment`）和每项一行
  （`usage-part`，`data-part`、`data-tokens`），一打开就显示；圆环的 `aria-describedby` 指向的描述换成各行（没有数据时仍是那句说明）。
  `store.ts` 的 `Tab` 加 `contextBreakdown`，`projects.ts` 的 `withInfo`、`actions.ts` 的 `refreshUsage` 跟着 `contextUsage` 一起写；
  `chat.css` 加分项的样式，`tokens.css` 加六个 `--color-part-*`。
- 去掉的：详情里那条圆环颜色的进度条（`.usage-bar span` 的样式、按 `fill` 定宽的 `span`）；只给说明用的 `-note` 描述元素换成
  说明与分项共用的 `-desc`。圆环本身（颜色分档、悬停、读屏名）不变。

## 窗口：圆环除以哪个窗口（规划时的提醒）

规划说"圆环除以第一个候选的配置窗口（modelSession.ts:1003），不是档案的有效窗口"。查下来：

- 圆环和分项用的都是 pi `getContextUsage()` 的 `contextWindow`（agent-session.js:3471）：它取 `_limitsModel()`
  （:311–313）= `routedModel?.model ?? this.model`。`routedModel`（:1045–1051）是虚拟模型下最近一次成功回复的实际模型。
  所以只有还没有成功回复时才是虚拟模型的窗口（第一个候选的配置窗口，modelSession.ts:1003）；有回复之后是那次回复的实际模型
  在 pi 里注册的窗口，也就是设置里填的 Context window（modelCompile.ts:78）。负责人的会话里助手消息带的是
  `api-deepseek-com` / `deepseek-flash`，窗口是它配置的 1,048,576。
- pi 判断要不要自动压缩用的也是回复的那个实际模型的窗口（agent-session.js:2376 `_modelForMessage`），条件是
  `tokens > window − reserveTokens`（compaction.js:173）。
- 档案的有效窗口（modelProfiles.ts:282，`min(配置, 服务报的)`，长输入测试判出静默截断时再降）只给 Mori 的模型层用
  （交接时放不放得下，modelContext.ts:423；模型行的 Use 提示）。
- 结论：圆环用 pi 的窗口是对的——"Autocompact buffer"和"Free space"要与 pi 什么时候压缩一致，pi 按配置窗口压缩。
  服务报的窗口比配置的小时，圆环和 pi 的压缩都按大的那个算，真正的上限更早到；要改就得把有效窗口编译进 pi 的模型
  （会改变 pi 什么时候压缩，是给模型看的变化），不在这个只改显示的包里做，列在下面"留给负责人"。负责人这台机器上两者相同：
  deepseek-flash 配置 1,048,576、服务报 1,048,576（model-profiles.json 的 `auto.reported`）；两个 GLM 模型服务没报，
  有效窗口就是配置的 1,048,576。

## 按推荐替负责人定下的（负责人没单独回答）

1. 分项一打开详情就显示，不像 Claude 那样再点"Context window"一行（诊断决定 1 的推荐）：详情里仍没有能停焦点的东西，
   不抢焦点、不挡快捷键的约定不变。
2. AGENTS.md 和记忆的四个分节合成一行"Memory files"（诊断决定 2 的推荐，Claude 的词），不分成"AGENTS.md"和"Memory"两行。
3. 名字照 Claude：System prompt、MCP tools、Memory files、Skills、Messages 在 Claude 的字串表里（`/rHnDpPaRk`、`GSCabmSClo`、
   `7nRj8nxT0m`、`EJSVsOA19u`、`hMzcSqn09p`）；System tools、Autocompact buffer、Free space 是 Claude Code `/context` 给的数据，
   Claude 桌面版原样显示（`c094b416e-*.js` 按这几个名字认 buffer 和 free）。
4. 只列算得准的八项；不做 Claude 的"Custom agents"、"Other"、"MCP tools"/"Memory files"的子列表、"Compact session"、
   "Last updated {time}. Send a message to refresh."、"Loading context breakdown…"。
5. 前五项按 Mori 的 `estimateMemoryTokens` 估（与记忆页、AGENTS.md 的 token 数相同），不用 pi 的字数 ÷ 4：负责人第一次请求
   服务报 2,354，Mori 估约 2.47k（高约 5%），pi 估约 1.95k（低约 17%，中文的 AGENTS.md 只算 284）。
6. Messages 取余下的（`tokens` 减去前五项，不小于 0），各项加起来等于第一行的用量，同 Claude。
7. 顺序固定（Claude Code `/context` 的顺序），不像 Claude 桌面版按大小排、颜色按名次给：颜色跟着分项、位置不随回复跳动
   （dataviz 的规则"颜色跟着实体，不跟名次"）；token 数为 0 的行不显示。
8. 颜色：dataviz 参考调色板里的六个（不用红色，红是圆环 ≥ 90% 的危险色）：System prompt 紫 `#6250d6`、System tools 青
   `#1baf7a`、MCP tools 黄 `#eda100`、Memory files 品红 `#e87ba4`、Skills 绿 `#008300`、Messages 蓝 `#2a78d6`；
   Autocompact buffer 灰 `--color-faint`，Free space 是条的底色 `--color-line`。可选的几项为 0 时不画，把所有组合都过了一遍
   `validate_palette.js`（白底、相邻）：正常视觉最差 ΔE 15.6（≥ 15），色觉异常最差 6.1（6–8 的下限带，靠段间 2px 空白和每行的
   名字、数补足）；青、黄、品红在白底上不到 3:1，每行写着名字和数。
9. 写法：估算的数前面加"≈ "（同第一行，Mori 对估算总加），Autocompact buffer 是设置的值、不加；百分比按窗口、一位小数
   （同 Claude 的 `toFixed(1)`）；读屏描述"<名字> approximately <完整的数> tokens (<百分比>)"，用", "连起来。
10. 窗口用 pi 的（见上面"窗口"一节），不换成档案的有效窗口。
11. 界面测试回放的旧录制里没有 `contextBreakdown`，按没有：详情只有第一行（状态表新加"回放旧的录制"一行）；不为此重录 fixture
    （这次不改模型看到或做的任何东西）。`?? null` 同 `memoryNotice` 已有的做法。
