# 选区、引用与反馈，回复下的操作（M4）

依据：方案 5.4（每条助手回复下的操作）、5.10、5.3（草稿含引用芯片）、第 4 节"选区反馈 · Mori"、
第 6 节（补充条目 id、`appendCustomEntry("mori.ref", …)`、Mori 自己保存的东西）。
右栏与文件阅读器见 [changes.md](changes.md)。M5 的会话引用（来源是另一个会话的几轮）见 [session-refs.md](session-refs.md)。

2026-10-20 负责人决定：

- 文件阅读器只用鼠标选字（鼠标是主要的选取方式），所以阅读器照 Claude 桌面版做语法高亮，不另做键盘选字；
  回复里的文字用回复下的"Attach message as context"也能只用键盘完成引用。
- 文件引用"Source changed"指引用的那段文字在文件里找不到了；文件别处改了、原文还在就跳到它现在的位置。
  只在你点芯片时检查，不监视文件、不在后台反复读文件。
- 选区浮层只在助手回复（含回复里的工具卡）和文件阅读器里出现，你自己的消息里不出现。
- 回复下的操作每轮一行，放在这一轮的最后。

## 开工前查的事实（pi 1.3.0 源码）

| 事实 | 影响 |
| --- | --- |
| pi 先把 `message_end` 发给订阅者，紧接着（同一段同步代码里）`sessionManager.appendMessage(event.message)` 写入会话，条目里存的就是这个消息对象 | 后台进程在 `message_end` 之后的微任务里按对象找到这条消息的条目 id，补发给界面（方案第 6 节第 4 件） |
| 每条消息都有 `timestamp`（ms），`message_start` 时就有，写进条目后不变 | 界面用"角色 + 时间"把补发的 id 对上对话流里的那一项；还没拿到 id 的回复（正在生成）用消息时间作锚点 |
| `appendCustomEntry(customType, data)` 写一条 `type: "custom"` 的条目，接在当前叶子后面；它不进模型上下文；`getBranch()` 会带上它 | 引用的来源写成 `mori.ref` 条目；重新打开会话时从当前分支读出来 |
| pi 的会话条目写入后不再改 | 回复里的引用不会"原文变化"，只会找不到（条目不在当前分支上） |

## 选区浮层

照 Claude 桌面版：选中回复里的文字，选区上方出现一个小浮层；点了之后选区清除、焦点回到输入框。

| 状态 | 来源 | 必须可见 | 可做的操作 |
| --- | --- | --- | --- |
| 选中回复里的文字 | 你用鼠标在一条助手回复里（正文、思考、工具卡的内容）选中文字，起止都在 pi 的同一条助手消息里 | 选区上方（上面放不下时下方）浮层（读屏名称"Selected text"）："Attach as context"、"Feedback" | Attach as context；Feedback；Esc 或点别处关闭；改选区 |
| 选中阅读器里的文字 | 你用鼠标在文件阅读器的内容里选中文字（行号不算进选区） | 同上 | 同上 |
| 不出浮层 | 选区跨了两条回复、在你的消息里、在界面文字（按钮、标题、阶段行）里、在工具卡的 diff 里（diff 画在 shadow DOM 里，选区读不到里面的字），或只选了空白；反馈表单开着时 | 没有浮层 | — |
| 流式输出中 | 选中的回复还在生成 | 浮层照常出现；新流入的文字不清掉选区；你在底部时，在对话流里按住鼠标、或有选区期间，对话流暂停自动跟随（下面有新内容时显示"Jump to latest ↓"），刚按下鼠标时字不会被滚走 | 同上 |
| 滚动 | 对话流或阅读器滚动 | 浮层跟着选区走；选区滚出它所在的区域（对话流或阅读器）时浮层隐藏 | — |

## 问 Mori（Attach as context）：输入框里的引用芯片

照 Claude 桌面版：引用放在输入框上方，显示来源和原文摘要，带 ×；发出后显示在你的消息上方。

| 状态 | 来源 | 必须可见 | 可做的操作 |
| --- | --- | --- | --- |
| 加入 | 你点了浮层的"Attach as context"，或回复下的"Attach message as context" | 输入框上方一个芯片：来源（"src/a.ts · lines 3–5"（一行时"line 3"）或"Response"）、原文第一行（截断，悬停看全文），读屏名称"Context: src/a.ts · lines 3–5, jump to source"；焦点到输入框末尾 | 点芯片回到原位置；×（读屏名称"Remove context: <芯片上的来源>"，悬停"Remove context"）移除 |
| 多个 | 再引用别处 | 按加入顺序排列 | 同上 |
| 重复 | 来源和原文都和已有的一样 | 不再加一个，焦点到输入框 | — |
| 草稿 | 芯片随草稿按会话文件存在本机（`localStorage` 的 `mori.draftRefs`） | 切换会话、去设置页再回来、重启后都在 | — |
| 只有芯片 | 输入框没有字 | "Send"可用 | Send |
| 发送 | `session.prompt` 带上芯片（`refs`）；发给模型的文字是引用块加你的文字（格式见下） | 芯片清空 | — |
| 生成中发送 | 排队（Queue）或插话（Steer）（Enter / Ctrl+Enter） | 排队区显示发给模型的全文（含引用块） | Withdraw、Stop 时排队区的全文放回输入框，引用块成为普通文字，芯片不恢复 |
| 发送时就失败 | `session.prompt` 失败，或后台进程发来 `mori.prompt_error`（带着这条消息的 refs） | 错误卡照常；"Put your last message back in the message box"放回你写的字，芯片放回芯片（已有的不重复） | Put your last message back in the message box |

发给模型的引用块（临时默认值，见 defaults.md）：每个芯片一段，段之间空一行，之后空一行接你的文字。

```text
Quoting src/a.ts, lines 3–5:
> export function add(a: number, b: number): number {
>   return a + b;
> }
```

只有一行时写"line 3"（"Quoting src/a.ts, line 3:"）；回复里的引用第一行是"Quoting your earlier reply:"。

## 发出的消息里的引用

| 状态 | 来源 | 必须可见 | 可做的操作 |
| --- | --- | --- | --- |
| 刚发出 | pi 记下你的消息后，后台进程写入 `mori.ref` 条目（`{ messageId, refs }`），并补发 `mori.entry_id`（带 `refs`） | 你的消息上方显示引用：来源和原文（最多 3 行，超出部分渐隐）；消息正文只显示你写的字 | 点引用回到原位置 |
| 重新打开、重启后 | 会话记录里的 `mori.ref` 条目，按 `messageId` 对上你的消息 | 同上 | 同上 |
| 对不上 | 消息正文的开头不是按 `refs` 拼出的引用块 | 按原文显示整条消息，不显示引用 | — |

## 回到原位置

只在你点芯片时检查来源（不预先读文件、不监视文件）；检查结果记在这次运行的内存里，芯片上的提示一直保留到下一次点它。

| 状态 | 来源 | 必须可见 | 可做的操作 |
| --- | --- | --- | --- |
| 回复里的选区 | 锚点：会话文件、这条助手消息的条目 id（还没拿到 id 时用消息时间）、原文 | 原位置不在已载入的 50 条里时先载入到它；滚到这条回复，高亮引用的文字约 4 秒（找不到对应文字时高亮这一条回复） | — |
| 整条回复 | 锚点同上，范围是这一轮的回复 | 滚到这一轮，整轮回复高亮约 4 秒 | — |
| 回复不在了 | 当前分支上找不到这条消息 | 芯片标"Source changed"，保留引用时的原文 | — |
| 文件里的选区 | 锚点：绝对路径、引用时的内容哈希（SHA-256）、行范围、原文 | 右栏打开阅读器；哈希没变：滚到原来的行并高亮；哈希变了：在文件里找原文，取离原来的行最近的一处，滚过去高亮 | — |
| 原文已变化 | 哈希变了、文件里也找不到原文 | 芯片标"Source changed"；阅读器顶部"Source changed · Attached text:"和原文，滚到原来的行 | — |
| 文件已被删除或移动 | 路径不存在 | 芯片标"File not found"；阅读器显示同样的字 | — |

## 反馈

| 状态 | 来源 | 必须可见 | 可做的操作 |
| --- | --- | --- | --- |
| 已有一张在写 | 表单开着时又点了"Give feedback" | 不换掉那张表单（免得丢掉写了一半的字），焦点回到它的输入框；表单开着时不出选区浮层 | 写完或关掉 |
| 打开 | 你点了浮层的"Feedback"或回复下的"Give feedback" | 浮层表单（读屏名称"Feedback"）：引用的原文（最多 4 行，可滚动）、"What result were you hoping for?"输入框（焦点在这里）、底部"This is only saved to Review and isn’t sent to the model. To have Mori act on it, use “Attach as context” instead."、"Cancel"和"Save" | 输入；"Save"或 Ctrl+Enter 提交；Esc 或"Cancel"关闭；点表单外面不关（免得丢掉写了一半的字） |
| 没写字 | 输入框为空 | "Save"不可用 | — |
| 保存中 | 主进程在写文件 | "Saving…"，按钮不可用；Esc 不关 | — |
| 已记录 | 主进程写好 `<userData>/feedback/<时间>.json` | 表单换成"Saved · View in Review"（M7 起"View in Review"是链接），约 3 秒后关闭；对话流、会话、模型都没有变化 | Esc 立即关闭；点链接打开工作回顾（Review）并选中这一条（[review.md](review.md)） |
| 保存失败 | 主进程写入失败 | 保留输入的文字，显示"Couldn’t save your feedback: "加原文 | 再试 |
| 流式输出中 | 引用的回复还在生成 | 表单照常；输入不被打断；引用的原文在打开时就定下来 | 同上 |

一份反馈记录（JSON）：时间、你的期望、引用的原文、范围（选区 / 整条回复）、锚点（回复：会话文件、条目 id、消息时间；
文件：路径、内容哈希、行范围）、会话（会话文件、工作目录、会话名）。反馈不经过后台进程和 pi，后台进程退出时也能记录。

## 回复下的操作

照 Claude 桌面版：一轮回复（你的一条消息之后、下一条之前的全部回复）只在最后一条助手回复下有一行操作；
最新一轮一直显示，较早的在鼠标悬停或键盘聚焦到这一轮时显示；复制后按钮短暂显示"Copied"。

| 状态 | 来源 | 必须可见 | 可做的操作 |
| --- | --- | --- | --- |
| 本轮结束 | 本轮不在生成（`agent_settled` 之后，或从会话记录载入） | 这一轮最后一条助手回复下："Copy"、"Attach message as context"、"Give feedback"（图标按钮，悬停提示和读屏名称是这几个字） | Tab 依次到达，Enter 执行 |
| 生成中 | 这一轮还在生成 | 不显示 | — |
| 本轮没有正文 | 这一轮只有工具调用、错误或停止 | 不显示 | — |
| 复制 | 你点了"Copy"：这一轮全部正文的 Markdown 原文，段之间空一行（不含思考和工具卡）；主进程写进系统剪贴板 | 按钮变成"Copied"约 2 秒 | — |
| 复制失败 | 主进程写剪贴板失败 | 按钮旁"Copy failed" | 再试 |
| 引用到输入框（Attach message as context） | 同"Attach as context"，原文是这一轮的全部正文 | 芯片"Response" | 同上 |
| 反馈这条回复（Give feedback） | 同"Feedback"，原文是这一轮的全部正文 | 反馈表单 | 同上 |

## 后台进程多做的事（方案第 6 节）

| 命令 / 事件 | 做什么 | 对应 |
| --- | --- | --- |
| `mori.entry_id` 事件 | 你的消息和助手回复写进会话后，补发 `{ role, entryId, time, refs }` | 第 6 节第 4 件"补充条目 id" |
| `session.prompt` 的 `refs` | pi 记下这条消息后，用 `appendCustomEntry("mori.ref", { messageId, refs })` 写进会话文件 | 第 6 节"引用来源用 pi 的自定义条目写进会话文件" |

主进程多的：`mori:read-file`、`mori:open-path`（阅读器，见 changes.md）、`mori:copy-text`（复制）、`mori:save-feedback`（反馈，第 4 节"选区反馈 · Mori"）。

## 反例

- 反馈不发给模型：提交后当前会话没有新消息，后台进程没有收到任何命令。
- 原文已变化（"Source changed"）时芯片仍显示引用时的原文，不换成现在的文字。
- 生成中选中文字、写反馈，新流入的文字不清掉选区，也不把输入框里写的字冲掉。
