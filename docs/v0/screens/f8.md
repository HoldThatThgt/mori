# 报告界面问题（F8，M2）

依据：方案 5.1（左栏底部入口）、5.15、第 6 节 `feedback.ts`。M7 的工作回顾（Review）里"UI issues"一节读取这里保存的文件
（v1：见 docs/specs/memory.md §10.8：工作回顾由记忆页替换，改为设置页的"UI issues"一节读取）。

## 入口

| 入口 | 来源 | 必须可见 | 可做的操作 |
| --- | --- | --- | --- |
| F8 | 你按了 F8；首次启动页、设置页、会话里都有效，焦点在输入框里也有效 | 先截下当前窗口，再打开报告框（截图里没有报告框本身） | — |
| 左栏底部"Report a UI issue (F8)" | 你点了它；左栏收起为图标栏时是一个图标按钮，悬停显示同一段文字 | 同上 | — |
| 已经开着报告框时再按 F8 | — | 不重复打开，焦点回到报告框的第一个输入框 | — |

后台进程退出后也能报告：截图和保存都在主进程里完成，不经过 pi。

## 报告框

| 状态 | 来源 | 必须可见 | 可做的操作 |
| --- | --- | --- | --- |
| 截图中 | 你按了 F8，主进程 `capturePage` 还没返回 | 什么都不显示（报告框要等截图完成才出现，免得截进图里），通常不到一秒 | Esc 取消 |
| 截图失败 | `capturePage` 报错 | "Couldn’t capture a screenshot: "加错误原文；仍可填写和保存（不带截图，文件里注明"Couldn’t capture a screenshot: <原文>"） | 填写、"Save"、关闭（"Cancel"） |
| 填写中 | 截图完成 | 截图缩略图；两个输入框"What went wrong"和"What you expected"；说明"Includes a screenshot, the current view, and your recent activity. Saved on this computer and never sent to the model." | 输入；"Save"（两个框都空时不可用）；关闭（Esc 或"Cancel"） |
| 保存中 | 你点了"Save" | 按钮显示"Saving…"，不可再点；"Cancel"和 Esc 都不起作用，等保存结束（免得看不到保存结果） | — |
| 已保存（v1：见 docs/specs/memory.md §10.9："View in Review"改为"View in Settings"，打开设置页的"UI issues"并选中这一份） | 主进程写完文件 | "Saved to <Markdown 文件路径>"；"Show in Explorer"；"View in Review"（M7；首次启动页和读取连接的页面上没有）；"Close" | "Show in Explorer"（资源管理器里选中这个文件）；"View in Review"（关闭报告框，打开工作回顾的"UI issues"并选中这一份，见 [review.md](review.md)）；"Close" |
| 保存失败 | 主进程写文件报错 | "Couldn’t save the report: "加错误原文；已输入的文字都还在 | 再"Save"；关闭（"Cancel"） |

- 报告框是浮层，在所有菜单和对话框之上（例如开着"Switch to “Allow all”?"时按 F8）：Esc 先关闭它（方案 5.8 的 Esc 顺序），不会停止生成；
  开着时 Alt+1 / Alt+2 / Alt+3 不会答复后面的批准卡。
- 打开报告框不影响正在生成的会话；关闭报告框后焦点回到打开前的位置。
- 没有填写就关闭时直接关闭；填写了一半关闭时也直接关闭（只是界面问题记录，不做草稿保存）。

## 保存的内容

保存在 `<userData>/ui-issues/`（临时默认值，见 defaults.md）：

- `<时间>.md`：时间格式 `YYYY-MM-DD-HHmmss`（本地时间），同一秒内再保存时加 `-2`、`-3`。
- `<时间>.png`：报告框打开前的窗口截图；Markdown 里用相对路径引用它。

Markdown 的结构（标题用英文，M7 按这些标题读取；完整的样子见 [../ui-strings.md](../ui-strings.md)"F8 报告"）：

| 一节 | 内容 | 来源 |
| --- | --- | --- |
| `# UI issue · <本地时间>` | 标题；时间格式 `YYYY-MM-DD HH:mm:ss` | 保存时刻 |
| `## What went wrong` | 你写的原文 | 你的输入 |
| `## What you expected` | 你写的原文；没写时为"(left blank)"（"What went wrong"也一样，M7 对照代码时补记）。M7 起，你写的行里像 Markdown 标题的（以 `#` 到 `######` 加空格开头）前面加 `\`，工作回顾按标题切节时不会被它切错 | 你的输入 |
| `## Screenshot` | `![Screenshot](<时间>.png)`；截图失败时写 `Couldn’t capture a screenshot: <原文>` | 主进程 `capturePage` |
| `## Current view` | 每项一行 `- <字段>: <值>`：Page（First run / Session / Settings / Customize / Review，还有 Loading… / Couldn’t load model settings；v1：见 docs/specs/memory.md §10.9：Review 换成 Memory，在设置页的 UI issues 时为 Settings）、Current session（会话名；没打开会话时 None，下面几项不写）、Folder、Session file、Model range（选择范围 `tab.pick`；没有时 None）、Model（当前的实际模型 `tab.current`；没有时 None）、Effort（Off … Max；不支持思考时 Unavailable；没有当前模型时 None）、Running（Yes / No）、Status line（阶段行文字）、Pending requests（等你批准的数量；协作模式：见 docs/specs/parallel-agents-taskboard.md §11.3：计入后台实例的批准卡）、Permission mode（Ask each time / Allow all）、Split view（分屏时）、Right panel（Open / Closed；2026-10-26 起右栏展开时 Open · Expanded）、Window size、Pane width（焦点所在那一栏 `.chat-pane` 的宽度，输入框下面一行按它分档；分屏右边那一栏比 `.pane-slot` 窄 1px；不在会话页时 None，右栏展开、会话面板藏起时也是 None）、Sidebar width、Right panel width、Background process。Model range、Effort、Pane width 是 2026-10-21 加的（[../composer-pickers.md](../composer-pickers.md)"我自己定的"第 16 条） | 界面状态（store）与窗口大小 |
| `## Recent activity` | 最近 30 条操作，每条带时间：发给后台进程的命令（只写类型和不含机密的摘要，例如发送的前 40 个字、批准的选择；连接表单只写"Save connection"，不写 key）、页面切换、按 Esc 停止、批准卡的选择（协作模式：见 docs/specs/parallel-agents-taskboard.md §13.10：`session.setTeam` 记 `Team <mode>`，`session.recheckAgents` 记 `Check agent files`，`session.stopTeam` 记 `Stop agents`，带 `team: 'once'` 的发送记 `Send (team): <摘要>`，`board.get` 不记；v1：见 docs/specs/memory.md §8"动作记录"：`memory.*`、`enhance.*` 的写命令与记忆页上的操作各记一条，读取类不记） | 界面里的操作记录（只在本次运行的内存里） |
| `## Versions` | Mori、Electron、Chromium、Node、Windows 的版本 | 主进程 |

API key 在任何情况下都不写进报告。

反例：截图里不出现报告框；连接表单里填过的 key 不出现在"Recent activity"里；按 F8 不会让正在生成的会话停止。
