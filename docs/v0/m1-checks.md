## 先确认：插话会不会跳过本轮剩下的工具调用

**不会，所以工具卡不需要"已跳过"。**

- 源码：pi-agent-core 1.3.0 的 `agent-loop.js` 只在一整批工具调用执行完（`turn_end` 之后）、下一次请求模型之前读取插话队列；
  停止（abort）才会让顺序执行的剩余调用不再开始。
- 真实录制 `tests/fixtures/m1/two-tools-steer.json`：模型在一条回复里调用两次 bash，插话在工具参数还在流入时发出
  （1251 ms，进排队区），两个命令都执行完（1380–4573 ms），插话在 4576 ms 的下一次请求前才送达。
  界面测试"steer：两个工具调用都执行完后插话才送达（不跳过）"回放的就是这段。

  又跑了 3 次打包程序，失败 1 次、通过 2 次（通过的两次带了进程诊断输出，失败没能复现到诊断里）。

## 测试中发现并已修正的问题

1. **停止后多出一张错误卡**：pi 停止时会以 `stopReason: error`、"This operation was aborted" 结束这条回复。
   实时运行时按"你按了停止"不显示它；从会话记录重新打开时 pi 没有"被停止"的标记，按 pi 的固定原文识别，显示"已停止"
   （登记为临时默认值）。
2. **首次启动测试成功后看不到首字耗时**：页面切到"打开文件夹…"时结果一起消失了；现在结果留在那一步。
3. **载入更早的消息后画面跳动**：代码高亮是异步的，载入后高度还在变；改为以原来最上面那条消息为锚点，之后交给浏览器的滚动锚定。
4. **代码块不换行、行内代码 11.96px**：streamdown 靠 Tailwind 类排版，本项目没有 Tailwind，补了对应样式；行内代码不小于 12px。
5. **编辑 diff 在窄栏里左右两列挤在一起**：改为上下合并、长行折行。
6. **页面控制台有一条 CSP 报错**：zod 定义 schema 时试探 eval；让它在任何 schema 定义前就不试探。
7. **流式输出很快时误报"有新内容"**：自动滚到底触发的 scroll 事件晚到，那时内容又长了一截，被当成你往上滚了。
   现在只有往上滚过上次自动滚动的位置才算离开底部（真实走查第一遍的压缩截图里出现过，修正后两遍走查都检查了）。

## pi 的行为（走查时要知道）

- **8k 上下文不改 pi 的设置就不会压缩**（走查 8）。pi 1.3.0 给输出预留 4096 token 的安全余量，加上约 3k 的系统提示，
  8k 窗口下每条回复只剩约 900 token，回复会在中途截断（`stopReason: length`），pi 用 `context_edit` 把截断的回复移出上下文；
  而默认的 `compaction.keepRecentTokens` 是 20000，比整个窗口还大，没有可压缩的旧内容。
  走查 8 的做法：上下文长度填 8000，并在 pi 的 `settings.json` 写 `"compaction": { "reserveTokens": 6000, "keepRecentTokens": 300 }`。
  这样第一轮之后就会压缩；聊得更久时，压缩本身也会因窗口太小失败（"Summarization failed: generation hit the token cap"），
  界面显示原文和"把上一条消息放回输入框"。内网模型的上下文如果也很小，需要你决定这两个 pi 设置怎么配。
- **key 写成 `$变量`**（走查 6 后半）：按你 2026-10-19 的决定，key 由 Mori 加密保存、不再支持 `$环境变量名`，
  所以 `$MORI_UNSET_KEY` 会按原样当作 key 发出去，看到的是端点的 401 原文和"去设置"。
  "找不到 key"现在对应"本机没有保存 key"：pi 报 "No API key found for the selected model"，同样附"去设置"。两种都走查了。
- 每次运行 pi 都先发一条 `system` 消息（工具与提示词声明），界面不显示。
- DeepSeek 会把思考和工具参数交错流出；`deepseek-flash` 的思考常常只有几十毫秒，"思考中"一闪而过是正常的。
- 后台进程在命令执行中被结束时，会话记录里那次调用没有结果；重新载入后继续对话，DeepSeek 能正常回答（它会提到上一条命令没有结果）。

## 与方案不同、或需要你决定的地方

1. **测试连接会先保存**：M0 是"没保存不能测试"；M1 首次启动的流程是"填好 → 测试连接"，所以测试前自动保存。
2. **左栏只列本次运行打开过的会话**：项目→会话树、新会话（Ctrl+N）、改名、删除、状态点都在 M3；M1 不放没有功能的入口
   （工具、工作回顾、F8 也不放）。
3. **右栏只有改动列表**：文件阅读器、点路径打开在 M4。第一次出现改动时右栏自动打开（登记为临时默认值）。
4. **顶栏没有思考强度和权限菜单**：分别在 M6 和 M2。每条回复下的复制、引用、反馈在 M4。
5. **命令进程可能比 Mori 活得久**：后台进程被强行结束时，正在运行的命令会跑到自己结束为止；正常关窗在完整冒烟里也偶发留下
   `sleep.exe`（见上文"没有查清的一项"）。和 pi #9129 是同一类问题。可选做法：主进程在退出和"重新载入"时，按启动时记下的
   后台进程 PID 找出所有父进程已不在的后代进程并结束它们（属于方案第 6 节主进程"有序关闭后台进程"的范围，不改 pi）；
   或者先不处理。请你决定。
6. **草稿只在本次运行里保留**：切换会话、去设置页、后台进程重新载入都在；重启 App 后保留在 M3。
   Electron 默认菜单的"重新加载"（Ctrl+R）会刷新页面，草稿和本次打开的会话列表会丢；要不要去掉默认菜单请你决定。
