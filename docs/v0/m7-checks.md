## 需要你确认的地方（都已按推荐做法实现，走查时可以改）

1. **分节上的数字为 0 时不显示**：状态表只说"各带未处理的条数"，没说 0 怎么显示；现在照未读数的常见做法，0 不占位置，
   读屏名称仍是"对内容的反馈，0 条未处理"（登记在 defaults.md）。另一种做法是一直显示数字，包括 0。
2. **原会话删掉后，文件里的反馈也不能回到原位置**：文件里的反馈的锚点是文件（路径、内容哈希、行范围），但阅读器在会话的右栏里，
   要先打开反馈时所在的会话；这个会话删了，详情就显示"原会话已删除"、按钮不可用，哪怕文件还在。另一种做法是没有原会话时
   在焦点所在的会话的右栏里打开这个文件。推荐现在的做法：与回复里的反馈一致，也不为回看反馈另找或新建会话（状态表反例
   "原会话已删除时不新建会话"）；详情里有文件的路径，可以在任一会话里打开它。
3. **回到原位置会把已归档的会话恢复**：与在侧栏点已归档的会话相同（M3），也与 M5 点会话引用相同；回看一次之后它回到项目下，
   不想留着要再归档一次。另一种做法是打开它但仍留在"已归档"里（M5 审查时改掉过这种"打开了却还在已归档列表里"的情况）。
   推荐现在的做法。
4. **M7 之前存的 F8 报告，"你期望什么"里写了一行"## 你期望什么"时切不准**：工作回顾按报告的标题切节。M7 起写报告时给你写的
   两节里像标题的行加 `\`，新报告没有这个问题；更早的报告不改（工作回顾只读不改），这种报告里那一行之前的字会被算进"哪里不对"，
   详情和导出都是这样。写在别处的标题行（例如"哪里不对"里写的"## 你期望什么"、任何一节里写的"## 截图"）不受影响
   （第一节取第一次出现，之后的从后往前找）。没有别的做法能在不改文件的前提下分清，只在这里说明。
5. **导出写反馈时记下的会话名**：列表和详情显示侧栏现在的名字（改过名的显示新名字），导出的文件写反馈当时记下的名字
   （导出在主进程里写，导出请求只带文件名，主进程不知道侧栏现在的名字；登记在 defaults.md）。改过名的会话两处会不同。
   另一种做法是界面把现在的名字随导出请求一起交给主进程。

## 测试中发现并已修正的问题

实现完成、`m7-app` 全部通过之后，做了一轮从五个角度的对抗式只读审查：共 45 条，确认 34 条并已修正，驳回 11 条。
之后打磨、录制、回放、走查时又发现几处。

1. **审查确认、已修正的**（主要的几条；每条都在 `m7-app` 里有对应的检查）：
   - 打开工作回顾之前截图的 PNG 就被删了时，这一行标"没有截图"、详情说"截图失败" → 列表不看 PNG 在不在，详情读截图时显示
     "截图读不出来："和原文（"截图失败"只用于报告里本来就写着截图失败的）；
   - 读不出来的反馈没法"打开所在文件夹"（M2 的 `mori:show-issue` 只认 `ui-issues`）→ 新增 `mori:review-show-record`，按类别和
     文件名选中，报告和读不出来的记录都用它；
   - 切换分节、离开工作回顾再回来后列表回到最上面 → 每个分节各自记住滚动位置（直到重启）；
   - 重新读取时上一次的列表没了、滚动位置丢了 → 上一次的列表留着，"正在读取…"显示在标题旁边；
   - 在"UTF-8 带 BOM"的编辑器里另存过的记录读不出来 → 去掉开头的 BOM；
   - 反馈按文件名（本地时间）排序，改过系统时区或夏令时回拨后顺序不对 → 按记录里的 `createdAt`；
   - 导出的截图链接在文件夹名里有 `#`、`%` 时会被当成网址的一部分 → 每一段按网址编码，链接写在尖括号里；
   - 你在"你期望什么"里写一行"## 你期望什么"会让报告切错节 → 写报告时给像标题的行加 `\`（旧报告见"需要你确认"第 4 条）；
   - 检查回复还在不在的时候你又点了别的"回到原位置"、或离开了工作回顾，检查完仍会打开先点的那个会话 → 只有最后一次点的、
     而且还在工作回顾时才打开，其余只记下结果；
   - 分屏放不下右栏时"回到原位置"（文件里的）打开了阅读器却看不见 → 右栏浮出来（"与方案不同"第 3 条）；
   - "隐藏已处理"开着时，关闭一条已经不列出的记录的详情，焦点掉到页面外 → 回到这一节的分节按钮。
2. **列表有横向滚动条，每一行的右边被切掉**（打磨时发现）：列表是 grid、没有列模板，那一列被最宽的一行（不换行的原文、来源、
   错误行）撑到 602px，而中栏只有 468px → `review.css` 给列表加 `grid-template-columns: minmax(0, 1fr)`，长期望在 2 行内截断、
   单行的以省略号截断；`m7-app` 加了三项，在默认大小、1200、1024、800 px 宽时量列表和详情有没有横向溢出（去掉这一行 CSS 时其中一项失败）。
3. **录制**：录制器想包住界面的 `saveIssue` 记下结果，但 `window.mori` 是冻结的 → F8 改为在界面里真的按、真的保存，从报告框读路径。
   让一条回复离开当前分支没有现成的操作 → "回复不在了"用 synthetic 记录（"与方案不同"第 5 条）。
4. **走查脚本自己的问题**：拖选的那段字结尾是空格时，Mori 存反馈前去掉了首尾空白，脚本拿没去掉的字比较，开发构建的一遍 2 项失败
   → 脚本也去掉（之后两遍选到的字结尾都不是空格，这种情况没有再走到）；从 Bash 传 `--exe` 用反斜杠时路径被吃掉，Playwright
   起不来并让 Node 直接退出，清理没跑，留下两个临时数据目录（已删）→ 用正斜杠。
