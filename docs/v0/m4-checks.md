## 与方案不同、或需要你注意的地方

1. **文件由主进程读**：方案第 6 节"后台进程只做四件事"里没有读文件；阅读器（方案 5.9）要读文件，而界面进程是沙箱。
   读文件、用系统程序打开、写剪贴板都放在主进程（与 M3 的"删除会话文件"、M2 的 F8 截图一样是系统操作），只读、不监视文件、
   不经过 pi。路径解析照搬 pi 的 `resolveToCwd` 规则（主进程不能 import pi），pi 升级时要对照。
2. **主进程读文件的范围**：只检查调用者是 Mori 自己的页面，不限制在项目文件夹里（模型可以改项目外的文件，工具卡里的路径要能点开）；
   网络路径不读也不打开。页面不能导航到别处、不加载远程内容，所以没有另外的限制。
   **"用系统编辑器打开"遇到会被运行的文件**（脚本、程序、快捷方式、安装包）不打开，改为在资源管理器里选中，并说明原因
   （方案写"用系统默认编辑器打开"，Windows 的"打开"对这类文件就是运行；Electron 没有"编辑"这个动作）。
3. **对内容的反馈存成 JSON**（`<userData>/feedback/<时间>.json`，每份一个文件，登记为临时默认值）。"在工作回顾中查看"在 M7 之前只是一行字，
   没有链接（工作回顾页还没有）。
4. **带引用的消息发给模型的是"引用块 + 你的文字"**（格式登记为临时默认值）。排队区显示的、撤回或停止时放回输入框的是这段全文，
   芯片不恢复；"把上一条消息放回输入框"也一样。会话名（没起名时取第一条消息的前 20 个字）遇到第一条消息带引用时会是"引用 src/a.ts …"。
5. **回复里的引用不会"原文已变化"**：pi 的会话条目写入后不改，只有条目不在当前分支上才会找不到；M4 里没有能造成这种情况的操作，
   所以回复引用的"原文已变化"只在逻辑上存在，没有在界面上走到（测试用"找不到这条回复"的情况覆盖了判断）。
6. **选区不能跨 pi 的两条助手消息**：一轮里工具调用前后的两段话是两条消息，起止分在两条里时不出浮层（锚点是一条消息）。
   要引用整轮用回复下的"引用到输入框"。右栏 diff（画在 shadow DOM 里）里的字也不出浮层。
7. **选区浮层只用鼠标**（你的决定），浮层的按钮在浮层出现后可以 Tab 到，但不会自动拿走焦点。浮层在 Esc 的浮层栈里（Esc 先关它），
   但不挡 Alt+数字和 Ctrl+N（它不盖住批准卡）。
8. **对话流里按住鼠标或有选区时暂停自动跟随**（显示"有新内容 ↓"），松开、清掉选区后下一次内容变化时接着跟随。方案 5.4 说
   "流式输出不打断……选区"；不暂停时刚按下鼠标，下面的字就被滚走，真实走查第一遍就是这样选错了字（见下"测试中发现"）。
9. **还在生成的回复上做的反馈只有消息时间、没有条目 id**（反馈立刻保存，那时 pi 还没写入这条回复）；M7 跳回原位置时按消息时间找。
   在回复还在生成时加的"问 Mori"芯片也只有消息时间；回到原位置时先按条目 id 找，没有就按消息时间找。
10. **阅读器的行高亮一直留着**，直到下一次跳转或重新读取；对话流里的高亮约 4 秒后消失。
11. **回复下的"复制"经主进程写剪贴板**。测试中发现 M1 代码块上的"复制代码"按钮点了不会复制：它用浏览器的剪贴板接口，而 Mori 拒绝
    页面申请的所有权限（M2 起）。你让我在这里一起修了（2026-10-20）：权限只放行 Mori 自己的页面写剪贴板这一项
    （`clipboard-sanitized-write`，`src/main/index.ts` `lockDown`），其余照旧全部拒绝；`m1-app` 加了一项检查。
12. **"打开"和工具卡路径用工具参数里的原文**交给主进程解析；同一个文件用相对路径和绝对路径改过时，改动列表按解析前的写法分组
    （工作目录之内的统一成相对路径比较，大小写不分）。

## 测试中发现并已修正的问题

1. **阅读器换文件时先闪一下上一个文件的内容**（读取是异步的，新文件读完之前还画着旧的），测试里表现为点了 A 却读到 B 的状态
   → 读到的内容按"路径 + 这次读取"记，换了文件或重新读取时立刻显示"正在读取…"。
2. **三击选行的修正把空行吃掉**：选区止于下一行行首时算到上一行为止，下一行恰好是空行时也被去掉了 → 下一行有字时才这样算。
3. **回复下的操作在你按下发送的一瞬间消失**（把"刚发出"也当成这一轮在生成）→ 只在本轮运行中、最后一条回复还在流入时不放在最后一轮。
4. **真实走查第一遍，流式输出时拖选选错了字**：鼠标按下的那一刻对话流还在自动跟随，下面的字被滚走 → 按住鼠标期间暂停跟随（见上第 8 条）。
5. **独立的代码审查**（看过 pi 源码核对时序，结论：补条目 id 的时序和 `mori.ref` 条目对 pi 的上下文、压缩都没有影响）提出、已修正：
   - **"用系统编辑器打开"会运行脚本和程序**：Windows 按关联程序"打开"`.bat`、`.ps1`、`.py`、`.exe`、`.lnk` 等就是运行它们，
     而这些文件可能是模型刚写的 → 这类文件改为在资源管理器里选中，并说明原因；网络路径（`\\主机\共享`）不读也不打开；
   - 发送时就失败的带引用的消息，"放回输入框"放回的是含引用块的全文、芯片丢了 → 放回你写的字和芯片（`mori.prompt_error` 带上 refs）；
   - 改动列表和阅读器按显示用的路径比较，`./a.ts`、`@a.ts`、`/c/...` 与绝对路径对不上：从引用芯片（绝对路径）打开的阅读器在文件被改后不重读
     → 按 pi 的规则把路径化成同一种写法再比较；
   - 跳到引用时，新内容读到的那一刻先画了上一次跳转的高亮 → 高亮在渲染时就按这次读到的内容算出来；
   - 阅读器选区的端点落在两行之间时按第一行 / 最后一行算（引用会一直延伸到文件头尾）→ 按端点的位置取那一行；
   - 工具卡里的 diff 画在 shadow DOM 里，页面的选区读不到里面的字 → diff 不当作引用来源（写进状态表）；
   - 选区滚到顶栏或输入框后面时浮层还浮在上面 → 选区滚出它所在的对话流或阅读器时隐藏；
   - 补条目 id 的微任务里出错会结束后台进程 → 接住并记日志；读文件时路径解析出错没有日志 → 放进 try；
   - 已有一张写了一半的反馈表单时，再点"反馈这条回复"会换掉它 → 不换，焦点回到它；表单开着时不出选区浮层；
   - 选区引用找不到对应文字时高亮了整轮（状态表写的是整条回复）→ 只高亮那一条回复；写入的改动缺"写入的内容"标签 → 补上；
   - 两个函数超过 50 行（对话流的跟随、输入框）→ 拆开；`app/package.json` 的换行被改成 LF → 改回 CRLF。
6. **环境**：这个 worktree 里 `npm ci` 没有装上 Electron 的二进制（这台机器的 npm 默认拦下依赖的安装脚本，提示 `allow-scripts`）→
   手动 `node node_modules/electron/install.js`（经 `ELECTRON_MIRROR`）。README 的准备步骤没有改，换机器构建时要注意。
