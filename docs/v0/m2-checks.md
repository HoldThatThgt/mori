## 开工前查的 pi 1.3.0 行为（对照源码，并由另一组核对）

| 事实 | 影响 |
| --- | --- |
| pi 先把 `tool_execution_start` 发给订阅者，再调用扩展的 `tool_call` 处理器 | 后台进程在转发 `tool_execution_start` 之前紧挨着发 `mori.tool_gate`，界面同一刻就知道卡是"等你批准"还是"执行中"，不会闪一下"执行中" |
| 默认 `toolExecution: "parallel"`：一条回复里的调用逐个经过处理器，全部放行后才一起执行 | 允许第一张卡后它不会马上执行；见下文"需要你决定"第 1 条 |
| 停止时 pi 不会替处理器取消等待，`session.abort()` 会一直等处理器返回 | 每个挂起的请求都监听 `ctx.signal`，中止时自己按拒绝返回 |
| 处理器返回后 pi 先看 signal：已中止就只记 "Operation aborted"，不看 block 的理由 | 有卡挂着时停止：先拒绝、等这次调用在 pi 里结束，再中止，会话记录里才留下拒绝 |
| block 的理由原样成为工具结果（`isError`），记录里没有"被扩展拦下"的标记 | 拒绝的理由用固定写法（`Rejected by the user…`），重新打开会话时据此显示"已拒绝" |
| inline extension 排在文件扩展之后；前面的处理器拦下时不会轮到它；扩展加载失败时会话照样创建，没有处理器就不询问 | 卡上的参数取处理器拿到的 `event.input`；批准扩展加载失败时不打开会话 |
| 内置工具没有 `readOnlyHint` 之类的标注 | 只读放行名单按工具名写成常量（read、grep、find、ls），与方案 5.7 相同 |

## 与方案不同、或需要你决定的地方

1. **一条回复里的工具调用按顺序执行**（pi 的 `toolExecution: "sequential"`，登记为临时默认值）。pi 默认并行：允许第一张卡后它要等后面的卡都答复才执行，
   多条命令会同时运行。按顺序执行时允许一张执行一张，看到上一条的结果再决定下一张（"逐张出卡"）。代价是模型一次读多个文件时也逐个执行。
   后面排着的调用显示新状态"等待执行"。**请你确认。**
2. **Esc 的两种情况**：方案 5.7 说"焦点在卡片上时 Esc 等于拒绝"，走查 6 说"有批准卡时按 Esc：按拒绝处理，并停止生成"。实现为：
   焦点在卡上（按钮或理由框）时 Esc 只拒绝这张卡、生成继续；焦点不在卡上（例如在输入框）时 Esc 是停止，挂着的卡按拒绝处理。
   有菜单或下拉开着时 Esc 先关它们。**请你确认这样理解对不对。**
3. **停止时卡挂着**：工具卡显示"已拒绝 · 你按了停止"（命令没有执行），对话流再留一行"已停止 · 已经做出的修改不会自动撤销"；
   后台进程先拒绝、等 pi 记下（最多 2 秒，临时默认值），再停止，所以重新打开会话后也显示同样的文字。
4. **回给模型的拒绝写法是英文**：`Rejected by the user.` / `Rejected by the user. Reason: <理由>` / `Rejected: the user stopped the run.`（临时默认值）。
5. **卡上多了三样方案没写的东西**（审查时发现的风险）：修改和写入单独一行显示完整路径（长路径不截断）；路径在项目文件夹之外（绝对路径或含 `..`）时警示；
   文字里有双向控制符或零宽字符时标成可见的"⟨U+202E⟩"并警示（防止卡上看到的顺序与实际执行的不同）。
6. **F8 截图时什么都不显示**：报告框等截图完成才出现，免得截进图里（f8.md 已改）。
7. **工具卡上的拒绝理由超过 40 字时截断**，悬停或展开看全文（临时默认值）。
8. **关掉了拼写检查**：见下文"测试中发现并已修正的问题"第 1 条。
9. **不在 M2 的**：扩展的界面请求（通知、确认、选择、输入）的转达与项目扩展、MCP 一起在 M3 / M6；
   嵌套调用（扩展里的工具调用别的工具）的更正逻辑只用模拟验证过，v0 目前没有会这样做的扩展。
10. **M0/M1 的测试**：命令和编辑现在要先批准，`m0-smoke`、`m1-app`、`m1-real` 打开会话后先经权限菜单切到"全部允许"再测原来的行为；
    `m1-record` 用不录进 fixture 的命令切到全部允许，M1 的回放不受影响。

## 测试中发现并已修正的问题

1. **Mori 启动后会连外网下载拼写词典**（M2 之前就有）：Chromium 默认按系统语言从 `redirector.gvt1.com` 下载词典，
   这台机器的代理让连接成功了，`m0-smoke` 的"对外连接只有配置的端点"因此失败（M1 那台机器上大概连不上，所以没暴露）。
   用 Chromium 的网络日志确认了主机名。修正：主进程把拼写检查语言设为空、窗口关掉拼写检查；之后对外连接为"无"。
2. **多视角审查**（规格、F8、后台进程竞态、界面逻辑、安全、约定与测试六组，每条发现再由一组反驳核对）确认 26 条，已全部修正或补测试，主要有：
   - 出卡时对话流变矮但不滚动，"等你批准"的工具卡被挤出视野 → 停在底部时跟随；
   - 长路径在卡片标题里被省略号截掉，看不到真正写到哪里 → 单独一行完整路径、项目外警示；不可见控制字符标出；
   - 焦点在卡上时 Esc 越过开着的下拉直接拒绝 → 先关浮层；F8 报告框被"切换到全部允许？"盖住、保存中按 Esc 会关掉报告框、
     报告框开着时 Alt+1 仍会答复后面的卡、小键盘 Alt 码会误批准 → 都已修正；
   - 后面排着的调用一直显示"准备中" → 新状态"等待执行"；本轮结束时还没执行的调用显示"已中断"；
   - 停止的等待期间排在后面的嵌套调用可能出卡或执行、预告"要批准"后实际不用批准时卡片停在"等你批准" → 停止状态与更正事件；
   - 长拒绝理由挤掉工具卡标题 → 截断；最小窗口下卡片加长草稿会把停止按钮挤出窗口 → 卡片内容区收缩、卡内滚动；
   - 测试：F8 报告"没有 key"的检查形同虚设、没有检查"新会话不继承全部允许"、录制脚本出错时留下复制的密文 → 已补。
