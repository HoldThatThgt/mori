## 照 Claude 桌面版

方案没定、按你的规则照 Claude 桌面版做的交互（Claude 桌面版的 Code 页可以把侧栏的会话拖到窗口一侧，或右键"在分屏中打开"）：

| 交互 | 照 Claude 桌面版的做法 |
| --- | --- |
| 怎样分屏 | 把侧栏的会话拖到中栏左半边或右半边，放下前那一半（分屏时是那一栏）上浮一层半透明的提示；也可以右键"在右侧分屏打开"。最多两栏 |
| 哪一栏是"当前" | 你最后点过（或键盘焦点进过）的那一栏，标题行底色变浅蓝、下边一条强调色的线；侧栏高亮它的会话，另一栏的会话行浅色标出 |
| 分屏时在侧栏点会话 | 换掉焦点所在的那一栏；点已在某一栏的会话只把焦点切过去。新会话（Ctrl+N）、打开文件夹也出现在焦点所在的那一栏 |
| 每一栏的标题行 | 会话名（可拖、可右键，菜单与侧栏相同，改名就在标题行上改）、模型、权限、上下文用量、右栏开关，分屏时多一个"关闭这一栏"（×）；栏窄时先藏项目名，再藏模型名和上下文用量 |
| 关闭一栏 | 只是不再显示，会话照常在后台运行（与 M3 起"会话不因不在屏幕上而停"一致）；回到单栏，另一栏得到焦点 |
| 附加到输入框的会话 | 输入框上方一个卡片（芯片）"引用 · 会话名 · 第 3–8 轮 · 约 3,200 字"，× 移除；点它打开一个对话框看全文（Claude 桌面版点附加的内容卡片也是打开对话框预览） |
| 发出后的会话引用 | 与 M4 的引用相同，显示在你的消息气泡上方（会话名和内容的前 3 行），点它回到原会话 |
| 点发出的会话引用 | 与在侧栏点这个会话相同（在焦点所在的那一栏打开，已在某一栏就切过去），滚到引用的第一轮并高亮那几轮约 4 秒 |
| 引用上的会话名 | 显示原会话现在的名字（改名后跟着变）；原会话删除后用引用时的名字 |

## 需要你确认的地方（都已按推荐做法实现，走查时可以改）

1. **点发出的会话引用在哪一栏打开原会话**：现在照"在侧栏点它"，在焦点所在的那一栏打开（这一栏原来的会话照常开在后台，侧栏点回去即可）。
   另一种做法是在另一侧分屏打开，两边对照着看。推荐现在的做法：行为与侧栏一致、可预期；想并排看时把原会话拖到中栏另一侧。
2. **分屏、右栏打开、窗口 1200 宽时**：右栏贴在右边，两栏正好各 280px，分屏中线没有可调的范围（不显示）。方案的规则是"两栏各不足 280px 时
   先收起右栏"，现在严格按这条做。如果你觉得 280px 太挤，可以改成分屏时右栏先让到最窄（260px）、或分屏时右栏默认收起。
3. **右栏开关在分屏时的按下状态**：两栏标题行各有一个右栏开关，按下状态表示"这一栏有焦点时右栏是否打开"，所以两栏可能同时显示按下。

## 开工前查的 pi 1.3.0 行为（对照源码）

| 事实 | 影响 |
| --- | --- |
| `SessionManager.open(path)` 读出会话文件，`getBranch()` 给出当前分支；对 pi 1.3.0 写的完整文件不写任何东西（只在最后一行缺换行时补换行，旧版本格式才改写） | 引用没打开的会话时，后台进程用它读当前分支（新命令 `session.read`），不创建 pi 会话、不加载扩展、不问信任 |
| pi 在一轮开始时就把你的消息写进会话，助手回复、工具结果陆续写入，`agent_settled` 时这次运行才算完；运行中送达的插话、排队消息也写成你的消息 | 后台进程在一次运行开始时（发出提示，或扩展发起的 `agent_start`）记下当时的叶子；生成中 `session.read` 只交出已完成的轮次：这个叶子之后最后一条你的消息开始的那一轮还在生成，之前的都已完成 |
| `appendCustomEntry` 写的条目不进模型上下文；改名只追加 `session_info`，会话文件路径不变 | 会话引用的来源（原会话的会话文件、第几轮、两端你的消息的条目 id）随 `mori.ref` 写进发出它的会话文件；改名、重启后照样能跳回 |
| 一个会话打开着时，由它自己的 `SessionManager` 写文件 | 引用开着的会话时读它自己的分支，不另开一个读者 |

## 与方案不同、或需要你注意的地方

1. **新增的后台进程命令 `session.read`**：方案第 6 节"历史"写的就是后台进程调用 `SessionManager.open(path).getBranch()` 把条目交给界面；
   会话引用要读一个没打开的会话，用的正是这个调用，不创建 pi 会话、不加载扩展、不问信任，也不写会话文件。为了"只取已完成的轮次"，
   后台进程给每个会话记下一次运行开始时的叶子（内存里，一个字段），这是这一里程碑唯一的非界面代码。
2. **引用的内容存了两份**：发给模型的消息全文里有引用块（M4 起的做法），`mori.ref` 条目里的 `quote` 也是同一段内容——原会话删除后，
   "原文仍可查看"靠它。一段 2 万字的引用会让这一条消息在会话文件里约占 4 万字。
3. **"原会话已删除"按 pi 的会话列表判断**：列表读完、里面没有原会话、本次也没打开它，就标"原会话已删除"；不去磁盘上查文件（不监视文件，与 M4 的做法一致）。
   会话文件被 Mori 之外的程序删掉时，要等下一次读取列表（启动、改名、归档、删除之后）才会标出；点引用时如果打开失败，会话横幅显示原文。
4. **引用的会话名**：芯片和发出的引用显示原会话现在的名字；发给模型的引用块里是引用时的名字（发出后不再变，`stripQuotes` 要按它认出引用块）。
5. **分屏不跨重启**：只保存分隔线的比例；重启后与 M3 一样不自动打开会话，也就没有分屏（登记为临时默认值）。界面重新加载（Ctrl+R）后同样回到单栏。
6. **右栏开关在分屏时浮出的右栏盖住右边那一栏的标题行**（与窄于 800px 时相同）；收起它用右栏自己的 ×。
7. **拖到已归档的会话**：已归档的会话行不能拖，菜单仍是"恢复、删除"；点一个指向已归档会话的引用会打开它，它在本次运行里出现在项目下，
   已归档列表里仍记着它（重启后又在"已归档"里）。
8. **M3 测试里的菜单检查**：M3 的测试断言菜单"正好三项"。M5 按状态表在菜单里加了两项，M3 的测试改为只看 M3 的三项
   （`m3-helpers.mjs` 和 `m3-replay.mjs` 的 `menuItems` 去掉 M5 的两项），这两项由 M5 的测试检查；M3 测的行为没有变。

## fixture（从真实会话录制）

`tests/ui/m5-record.mjs` 经界面用的进程桥对 DeepSeek 发命令，录下命令、结果和全部事件；每个场景用新的临时数据目录和一次新的启动。
带会话引用的消息的全文和 refs 不照搬代码：录制脚本用 esbuild 把界面的 `sessionRefs.ts`、`quoteText.ts` 打包后直接调用，与界面拼出的完全一样。
6 个场景，录下的文件里没有 key（已扫描）。`ref-turns` 录了两次：第一次 DeepSeek 在第 2 轮用了命令（`ls; cat`）读 README，录制器只允许读取、
拒绝了命令，第 2 轮就没有成功的工具输出；改为也允许命令后重录，核对"工具调用只有一行标题、没有工具输出"。

| fixture | 内容 |
| --- | --- |
| `split-approvals` | 同一项目的两个会话各发一条要批准的消息（左边 edit 改 README.md，右边 write 新建 notes.md），按到达顺序各自允许 |
| `split-esc` | 左边运行 `sleep 37`（允许），右边写一段长回复；右边生成时停止左边（先撤回排队、再停止），右边照常写完 |
| `ref-turns` | 会话 C 先有 6 轮（第 2 轮读 README.md），重启；新会话 A 引用 C 的第 3–5 轮发出；C 改名；点引用打开 C；删除 C |
| `ref-reopen` | C（3 轮）和 A（引用 C 的第 1–2 轮）建好后重启；打开 A，点引用打开 C |
| `ref-running` | C 的第 3 轮正在写长回复时 A 引用 C：只读到已完成的 2 轮 |
| `ref-long` | C 有 6 轮很长的你的消息（每条约 4,500 字），全部超过 2 万字：默认只引用第 2–6 轮 |

## 测试中发现并已修正的问题

1. **M1 的窄窗口检查失败**（m1-replay、m1-app 的 800 宽）：标题行的会话名改成可拖的按钮后多了左右 4px 内边距，800 宽、右栏打开、中栏只有 300px 时
   标题行比原来宽了 8px → 去掉左右内边距。
2. **分屏后第一帧两栏宽度不对**（真实走查的截图里看到左栏短暂只有 237px）：左栏宽度原来按量到的中栏宽度算，分屏那一帧量到的还是单栏时的宽度
   → 两栏宽度改由 CSS 按比例算（`clamp(280px, 比例, 100% − 280px)`），量到的宽度只用于分隔线的数值。
3. **菜单"在右侧分屏打开"之后焦点有时没进新一栏的输入框**：菜单关闭后它在浮层栈里的登记要到下一次提交之后才去掉，放焦点时还以为有浮层
   → 放焦点前最多等 5 帧。
4. **生成中排队或插话的消息送达后，前一轮仍被当成"还在生成"**：最初按"一次运行开始时的叶子"整段排除 → 改为只排除最后一条你的消息开始的那一轮
   （下一条你的消息送达时上一轮就完了，与方案"一轮"的定义一致），`m5-app` 加了一项检查。
5. **录制**：`ref-turns` 第一次录的时候 DeepSeek 用命令读 README、被录制器拒绝，第 2 轮没有工具输出可查 → 允许命令后重录。
6. **测试自己的问题**：拖分屏中线的落点用了拖动前的位置；1200 宽、右栏打开时两栏正好 280px，中线没有可调的范围（改为先拉宽窗口，并单独检查这种情况下中线不出现）；
   浮出的右栏盖住了右栏开关（改用右栏自己的 ×）；助手回复按 Markdown 渲染，引用块的 `>` 不在文字里；菜单刚关闭的下一帧焦点回到会话行，测试按键太快。
7. **Windows 上 Python 改文件时把 LF 换成了 CRLF**：提交前按原来的换行写回（只影响我改过的文件，内容没变）。
8. **独立的代码审查**（对照 pi 源码核对了"一次运行开始时的叶子"在排队、插话、扩展命令、停止、发送失败时都记得对；结论：没有严重问题）提出、已修正：
   - 还没有消息的会话拖到输入框上时会分屏（违反"拖到输入框上不会分屏"）→ 输入框上不能引用时就不能放下；`m5-app` 加了一项检查；
   - 点引用时原会话正在打开或打开失败，会被误标"原文已变化"→ 与在侧栏点它相同：打开失败的先重试，正在打开的等它打开完，只有打开好了、
     找不到那几轮才标"原文已变化"；
   - 原会话已归档时点引用，打开了它却还留在已归档列表里 → 与在侧栏点已归档的会话相同，先恢复再打开；`m5-app` 加了一项检查；
   - 从标题行菜单删除会话时，确认框在被删的那一栏里，删除时这一栏先关闭、确认框跟着消失，删除文件失败的原文就看不到了 → 确认框挂到面板之外；
     `m5-app` 改为从标题行菜单删除；
   - 本轮开始时的叶子不在当前分支上时（扩展在运行中换了分支）会交出整段分支、把正在生成的一轮也带上 → 这时一条也不交；
   - `session.read` 把整段分支（含工具结果里的文件内容、命令输出、图片）交给界面，每次引用、打开预览都搬一遍 → 只交出你的消息、助手回复和
     `mori.ref` 条目（照你"不能无限量地用内存换性能"的要求）；四个引用的 fixture 按新的结果重录；
   - 分屏放不下、你点开浮出的右栏后去设置页再回来，右栏又浮出来 → 换页面时收起；"引用会话"在操作记录里记了两次 → 只记一次。
9. **M3 的测试**：标题行的会话名改成按钮后多了一个 Tab 停靠点，M3 走查 2"从输入框 Shift+Tab 回到会话树不超过 6 次"变成 7 次 → 会话名不占
   Tab 停靠点（键盘用侧栏会话行上的同一个菜单），M3 的路径不变；M3 测试的键盘选菜单项最多走 4 步，菜单多了两项 → 放宽到 6 步。
